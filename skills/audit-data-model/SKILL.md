# 审计数据模型自洽性

接手或重构任何 DB 项目(Spring+JPA/MyBatis、Django ORM、Prisma…),当 schema/种子感觉"建表没考虑关系"时,
在往上面写功能之前先跑一遍这个审计。目标:找出"实体存在、但关系/数据其实对不上"的地方。

## 何时触发
- 接手别人的项目,看不懂业务、觉得表关系乱。
- 重构前摸底,或加新功能前确认地基稳。
- 用户说"框架搭得一坨 / 表关系没考虑 / 数据对不上 / 有没有孤儿数据"。

## 步骤

### 1. 读四类源(光看建表 SQL 看不出问题)
- **建表 SQL / Flyway / Liquibase 迁移**:列、外键(往往没有)、唯一键、索引。
- **种子代码**:DataInitializer / import.sql / seed 脚本 / fixtures —— 暴露"喂没喂饱"。
- **实体 + Service 的写操作**:save / update / delete / audit —— 暴露"建组织带不带账号""状态改了级不级联"。
- **读取路径(Mapper/SQL/VO 组装)**:查一次"从父实体这边看子实体"的加载逻辑 —— 暴露"外键填了但反向 join 没接通"(借阅记录有 user_id,但用户详情没聚合其借阅)。光看写路径发现不了这类,必须读 mapper。

### 2. 逐条扫"坏味道"
- **空壳实体**:组织/目录表建了,但子数据(商品/门店/订单)只属于其中一个租户,其他是空壳。
- **硬编码 id**:`setCompanyId(1L)`、假设某行永远是 id=1;或 varargs/方法签名把实参吞掉(如公司 id 被当门店 id)。
- **脱节 free-text**:联系人/负责人是手填字符串,本应外键到账号/实体表。
- **建组织不带账号**:有登录角色的实体(公司/机构)save 只 insert 组织,不像"医师"那样建账号+档案一体。
- **状态位不级联**:停用/审核改了状态,但关联账号/子项没同步(停用了照样能登录)。
- **零种子核心流**:头牌业务流(下单/反馈/审批)完全没有种子,登录即空、看板全 0。
- **引用列悬空**:city_id / company_id 建了,但部分城市/公司没有任何子数据(查了也是空)。
- **反向遍历缺失**:FK 是填了(A→B 有值),但从 B 这边**看不到**它的 A(借阅记录有 user_id,但用户详情/列表没 join 出借阅;订单有 customer_id,但客户档案查不到订单)。记录明明存在,父视图却为空。根因在读路径 mapper/VO 漏了 join,光看建表/种子发现不了 —— 这类最坑,要靠"换到父实体视角点开详情"才暴露。
- **派生字段/时态漂移**:某字段**定义上**是别的字段的函数,却被独立写值、与源对不上。典型:逾期日=借阅日+借期(种子各写各的→对不上)、订单总额≠明细求和、库存≠初始−售出+补货、状态位(逾期/已完成)与时间字段矛盾。种子/批量导入时尤其高发。

### 3. 出证据表
每条 `文件:行 → 后果`,不要空谈。例:`DataInitializer:181 setCompanyId(1L) → 扬子江销售无法正确归属`。

### 4. 批量修(别打地鼠)
同一类病一次治完,不要一个个补:
- **种子自洽**:每家租户、每个目录都有像样数据,不再只喂饱一家。
- **关系互链**:组织带账号、联系人取账号姓名、引用列填实。
- **状态级联**:停用/审核联动账号与子项状态。
- **核心流跨状态播种**:待处理/处理中/已满足/已驳回 都有种子。
- **反向遍历补全**:为缺失方向补 mapper join / VO 聚合字段(用户能查到借阅、客户能查到订单),别只在子表留 FK 就完事。
- **派生字段从源算**:派生值在种子/写入时**由源字段计算**(overdue=borrow+借期),别手写;并校验状态位与时间字段不矛盾(标"逾期"但 overdue_date 还在未来=错)。

### 5. 核验
- 不能编译时,**逐文件读回**核对(导入、字段名、方法签名、实参个数)。
- 种子若只在"库为空"时跑(幂等 seed),要明确告知用户:**删库重建**才能看到新种子,否则跑的还是旧的。
- 整改写一份 md(放后端根目录等约定位置)供对接。

## 红线
- 别只看建表 SQL 就下结论——种子和 Service 才暴露"喂没喂饱"。
- 报告必须带 `文件:行` 证据,不臆测、不嘴硬(用户说关系乱时,先验证再认)。
- 修完别自动 push / 自动开浏览器,等用户指令。

## 关联
- 建模时的常驻偏好见 memory `data-model-must-be-coherent`(本 skill 是"显式审计",那条是"一直生效的设计自觉")。
