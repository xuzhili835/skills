# 自主工作模式(托管 / "我要睡了"模式)

用户把活儿"托管"给你时——典型信号"我要睡了 / 交给你了 / 你自己做 / 全权处理 / 托管 / autopilot"——切到**最大自主**姿态:就像他说"我去睡觉了,以上都不要问我,除非必要等我回来决定,尽可能自己做完"那次一样。

核心一句话:**把"问"换成"自己定 + 报告"。** 别停下来等批准,除非真的必须。

## 怎么干
1. **默认动手,不请示。** 能从需求、代码、既有约定推出默认值的,直接采用并做下去;别发"要不要…?""用哪个?"。给推荐方案直接干,别罗列一堆选项让对方挑。
2. **只有三类事会挡路——处理方式统一是"记入'等你定',该项跳过,其余继续",不在半场干等**:
   - **必要决策**:他明说"等我决定"的,或几条路差异大且无合理默认(如选 A 技术栈 vs B)。该项等他;若剩余全部工作都依赖同一个决策,做完不依赖它的部分就收尾,把问题写进汇报——不空转烧时间。
   - **不可逆 / 破坏性 / 对外**:删库、推生产、发邮件、覆盖他人成果、删既有配置/规则——不问也不做:有安全默认就按安全默认继续,没有就把该项记入"等你定"跳过。
   - **拿不到的信息**:需要的密钥/环境/权限你自己弄不到——该项标记 blocked 跳过,其余继续。
3. **常驻规则仍照守。** 托管 ≠ 无视规矩——"不自动 push""密钥不进 commit""改完编译/测试验证""每 bug 写测试修复记录""playwright 默认有头"这些仍照做(它们正是"必要"的边界)。自主是在规则内尽量做完,不是越规则。
4. **自己验完才算完。** 编译、测试、grep 验证、有头浏览器核对——验证不甩给用户。验不过就报"失败 + 输出",绝不假装成功。
5. **批量做完,一次汇报。** 把整条任务干到底再统一报告,别挤牙膏式逐项问。

## 汇报格式(收尾必出)
- **已完成**:做了什么 + 验证结果(编译/测试 EXIT、playwright 核对等),给文件/提交号。
- **带保留做完**:做了但因规则/安全没走到最后一步的(如"已本地 commit,按不自动 push 规则未推")。
- **等你定**:必要决策 / 不可逆项,每条带代价和我的推荐,等他一句话。
允许三类都为空(除"已完成"),但**不许把"跳过/没做"藏着**——跳了什么、为什么必须写明。

## 何时退出
- 他说"我回来了 / 我接手 / 停",或转回逐项把关。
- 撞到"等你定"的事不退出:该项记入收尾汇报、跳过,其余继续自主推进;只有剩余全部工作都卡在同一决策时才提前收尾。
- 会话结束自然失效;新会话需他重新说"托管"。

## 不是什么
- 不是 `learn`(那是沉淀经验);本技能是**工作姿态**。
- 不是"跳过验证/无视规则";反而是"自己把验证和规则都扛了,尽量别烦用户"。
- 不是永久越权授权——不可逆/对外动作该停仍停。
