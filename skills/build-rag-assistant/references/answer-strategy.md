# 三分支作答、拒答检测、无数据引导、来源回传

> 对应正文:**层 4 / 5 / 6 / 7**。讲"模型怎么作答、怎么确定性识别越界、查不到时怎么把用户引走、答案怎么可溯源"。这是这套助手区别于"裸调 LLM"的核心。

## 层 4:三分支作答 prompt(关键)

作答的 system prompt 拆成三分支判断,**措辞刻意分流**:
- ① **输入是纯闲聊 / 感叹 / 脏话 / 玩梗 / 与业务完全无关**(无任何业务问题)→ 只回一句**固定拒答句**(如"该内容不在知识库服务范围,请提出与…相关的具体问题"),不复述资料、不改写此句;
  - ⚠️ **含业务问题的混合输入走 ②,别走 ①**:如「你好,请问有阿司匹林吗?」「哈喽,住院怎么报销?」——虽有寒暄但有清晰业务问题,按 ② 正常作答(可顺带回应寒暄)。① 只挡**纯**无关输入;连「寒暄 + 业务」一起挡会让助手僵硬、误拒正经提问。
- ② **正经业务问题、资料能答** → 依据资料简明作答,用 `[序号]` 标来源;资料未覆盖处可用通用知识补充并注明「(通用知识,非本平台数据)」;
- ③ **正经业务问题、资料答不了**(实时库存数、某网点营业额等平台动态数据资料里没有)→ 如实说**「知识库暂无该数据」**,措辞**与①刻意不同**,可一句话引导去对应业务页面,不复述无关资料。

> 坑:若 ①③ 同用一句拒答,正经的"无数据"问题会被误判成越界垃圾话。**措辞分流 = 下面确定性识别的钩子**——它让"无数据"和"越界"能用一句话区分开。贴资料作答时 temperature 调低(如 0.2)少发挥。

### 计数/规模类问题:注入实时数据(别用文档里的旧数字)

"有多少个销售网点""医师多少人"这类计数问题,知识库文档里的数字是**导入时的快照、会陈旧**;模型只认文档、不会查实时库,会答出与当下不符的旧数字(甚至被旧文档带偏成错误值)。
- 识别计数类提问(关键词:多少 / 几个 / 几[家位人种] / 数量 / 总数 / 共有 / 规模…);
- 命中时,把平台**实时规模**(从业务库 count 出来的公开数据)拼成一条资料,**前置注入**并标明"以此为准、优先于文档里的旧数字、作答无需为本条标来源序号";
- 走正常 ② 分支作答(`mode=local`),答案用实时真值,而非陈旧文档计数。

## 层 5:越界 / 拒答检测(确定性,不靠 LLM 自觉)

`RefusalDetector.isRefusal(answer)` 按**①的固定拒答句**做 `contains` 判定,**不靠 LLM 自觉"别答"**(LLM 不可靠地遵守"无关勿答"指令)。命中 → 清掉松匹配来源 + 标 `out_of_scope`。
> 因层 4 里 ①③ 措辞不同,③ 的「暂无该数据」**不含**①的拒答句 → 不会被误标成越界。这就是措辞分流的目的。

## 层 6:无数据 → 挂引导跳转(把用户送去能查到数据的页)

branch ③「暂无该数据」时,LLM 不会追加动作标记、且往往没贴题来源 → 常规动作解析拿不到按钮。这时按**问题 query 里的主题词**挂 1 个跳转,引到能查到该数据的业务页(问"哪个药库存最低" → 「↗ 药品库存」按钮)。
- 主题词表 `route → topic`,遍历**当前角色可见的目录**,首个命中的 topic 挂 **1 个**按钮(别一串);
- **必须用原始 query**,不能用拼了目录的 prompt 文本(后者含路由名会误命中);
- 只给该角色真有权限的页(目录即白名单)——没库存页的角色就不挂。

### 动作解析的闸门(防 LLM 硬塞无关按钮)

LLM 在答案末尾用 `[[ACTION|label|route]]` 标记自定跳转,解析时过几道闸:
1. target 必须是本角色合法路由(防臆造 / 越权);
2. label 用目录标准名覆盖 LLM 自拟文字(防"查看企业"张冠李戴);
3. 主题词须出现在**最相关来源标题或用户问题 query** 里(防"讲药企却冒出临床反馈按钮";只认来源标题会误杀合理跳转,故同时认可 query);
4. 无数据兜底引导(本层)在动作为空且判「暂无该数据」时触发。

## 层 7:来源回传(可溯源)

命中片段回传 `{title, snippet, docId, score}`,序号对齐正文 `[序号]`。前端渲染成「循证来源」面板,让答案可核对、抑制一本正经地胡说。
- **拒答时清空来源**(别"拒答却列 5 条来源"——被清的来源本就与答案无关);
- snippet 截断(如 120 字),score 透传便于前端可选展示。

## 失败 / 降级路径(不只画正常流)

正常流(建库 → 检索 → 作答)之外,这三个边界必须显式定义,否则线上会以"卡死 / 长转圈 / 假数据"暴露:
- **空库首启**(向量库 0 条):别让模型对着空资料硬编。检索前判 `向量数 == 0` → 直接 `mode=no_data` + 固定提示「知识库正在建设中,暂无可答内容」,**跳过作答调用**(省配额、防空库乱答)。后台可挂「去管理台导入知识」引导。
- **配额耗尽 / 鉴权失败**(Provider 返回 401 / 402 / 429):不可静默吞。标 `mode=error`,前端显「AI 服务暂时不可用,请稍后重试」+ 重试;**不要**降级成 `mode=general` 通用兜底(那是"本地 0 命中"的语义,混淆了"没数据"和"服务挂")。
  - 可选:**自动切回 stub / templated Provider 保可用**——用**熔断器(circuit breaker)**形状,三态:`CLOSED`(正常用真实 Provider)→ 连续失败累计到阈值 → `OPEN`(熔断,全走 stub 保可用)→ 定时探活 → 成功则 `HALF_OPEN` 放少量请求试通 → 通则回 `CLOSED`。**参考阈值起点**:连续 **3~5 次** `mode=error`、或 1 分钟内探活连续失败 → 熔断;每 **30~60s** 探活一次(发一个最小 chat 请求)判定恢复。
  - ⚠️ 熔断期间**前端仍可用**(stub 答案 +「降级模式」标识),别整页灰掉;熔断 / 恢复事件要落日志或告警;务必实现**切回探活**,否则切到 stub 就回不来。本节给形状 + 阈值起点,完整状态机属进阶、按需实现。
- **网络超时**:作答调用设超时(如 30s),超时 → 同上 `mode=error` + 重试入口;检索(本地)一般不超时,若向量库远程化则同样兜底。
> 判定原则:**"服务异常"和"没数据"是两回事**——前者 `mode=error`(系统态,引导重试),后者 `mode=no_data`(业务态,引导跳转)。别用同一个 mode,否则用户分不清是该重试还是该去别的页查。
