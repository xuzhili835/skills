# 前端悬浮精灵对话框

> 对应正文:**层 12**。讲"悬浮 AI 对话框的工程细节"。**框架无关(Vue / React 同理)**,重点是不踩样式隔离 / 用户隔离 / 渲染安全 / 状态显示的坑。

## fab + 面板:portal 出去 + 样式隔离
- fab(悬浮按钮)+ 展开面板,必须 **portal/teleport 到 body**(Vue `<Teleport to="body">` / React `createPortal`),脱离宿主页面样式作用域、浮在所有内容之上。
- 样式**非 scoped + 加前缀**(如 `.kb-fab-*`):被宿主 `.button`/`.card` 等通用选择器污染是常见坑;别用裸 class。
- z-index 拉到顶层(如 `9999`),并确认宿主没用更高值盖住。
- **前缀扛不住宿主污染时 → 升级 Shadow DOM**:宿主若用 CSS Modules / Tailwind `@apply` / 高特异性全局选择器,加前缀的**非 scoped** 样式仍可能被覆盖。这时把 fab + 面板挂进 **Shadow DOM**(宿主样式进不来、fab 样式也不污染宿主,硬隔离)。代价:事件冒泡被 shadow boundary 拦(需 `composed: true` 或 retarget)、字体 / CSS 变量不自动继承(要在 shadow root 重声明)、portal 目标改成 shadow root 而非 body。
- **iframe 嵌入是另一种部署形态**:fab 若跑在 iframe 里(跨域宿主),和宿主页面**不能用 DOM 直传**,走 `postMessage` 协议(宿主发 query、iframe 回 answer);样式天然隔离但生命周期 / 可见性跟 iframe 走。这是独立决策,别和 portal 方案混。

> Shadow DOM / iframe 嵌入是**独立的前端集成工程**(各有完整的事件 retarget / 通信握手 / 样式课题),本 skill 只给**方向 + 代价**,不给完整实现——需要时按方向单独立项,别指望这里能直接抄。

## fab 拖拽:会话内有效、重进重置
- 指针事件(pointerdown/move/up)实现拖拽,dragend 时 **clamp 到视口内**(别拖出屏)。
- 位置**只存 `sessionStorage`,不落 `localStorage`**——落全局会跨用户串位(上个用户拖到角落,下个用户接着用)。
- **"会话内有效" = `sessionStorage` 语义,边界要写明**:同一标签页**刷新页面位置保留**、**关页 / 关标签才重置**回默认位——即"会话" = **单标签页会话**,多标签页打开同一应用各自独立、位置不共享(这是 `sessionStorage` 的标准隔离,通常符合预期)。别用模糊的"会话内存"措辞——组件 state 刷新就丢(每次刷新重置,不符合预期),`sessionStorage` 才是"刷新留、关页走"的正确载体。
- ⚠️ **移动端 / WebView / PWA 边界**:`sessionStorage` 的"关页清空"依赖浏览器实现,在 Android WebView / 某些 PWA 容器里关标签未必触发清空、可能残留。若目标含这些环境,**别依赖精确清空时机**——要么接受"可能多保留一会"(无害,只是位置没重置),要么改成"每次进入组件即重置默认位"(最稳,代价是刷新也重置)。

## 四态显示各异(按后端 mode 区分,核心 UX)
- `local`(资料作答):正文(MD 渲染)+ 循证来源面板 + 可点动作按钮;
- `out_of_scope`(越界拒答):只显拒答句,**无来源面板**;
- `no_data`(无数据):「暂无该数据」+ 1 个引导跳转按钮(限当前角色可见页);
- `error`(服务异常):友好提示「知识库暂时不可用,请稍后重试」+ 重试;
- `general`(通用兜底):正文 + 「通用知识 · 非本平台数据」标识。
> 拒答时务必**清空来源显示**,别「拒答却列 5 条来源」。

**各态布局示意(别实现成"都长一样")**:
```
 local          out_of_scope      no_data          error           general
┌───────────┐   ┌───────────┐     ┌───────────┐    ┌───────────┐    ┌───────────┐
│ 答案正文   │   │ 一句拒答   │     │ 暂无该数据 │    │ 服务暂不  │    │ 答案正文   │
│ [1][2]... │   │  (仅此)   │     │ ↗ 去XX页  │    │ 可用      │    │(通用知识) │
│───────────│   │           │     │           │    │ ↻ 重试    │    │───────────│
│ 来源面板   │   │ (无来源)  │     │ (无来源)  │    │ (无来源)  │    │ 来源面板   │
│ 1.… 2.…   │   │           │     │           │    │           │    │ 1.… 2.…   │
└───────────┘   └───────────┘     └───────────┘    └───────────┘    └───────────┘
 正文+来源+动作  最简、只一句      无来源+1 跳转    无来源+重试      正文+来源+通用标识
```

关键差异:**来源面板只在 local / general 有**(拒答 / 无数据 / 异常都清空);**按钮只在 local(动作)/ no_data(跳转)/ error(重试)有**;general 多一条「通用知识」标识。

## 循证来源面板(签名元素,做精)
命中片段渲染成可点列表:序号 + 标题 + 摘要(`snippet` 截断 ~120 字)+ 可选 score。序号与正文 `[1][2]` 对齐。这种助手的可核对性全靠它,值得花时间——别省成纯文本。

## 动作按钮:只渲染后端过闸后给的
后端动作解析过了闸门(见 `answer-strategy.md`)才回按钮;前端只渲染后端给的,**别自己再判权限**(会与后端不一致)。无数据兜底按钮同理,只给当前角色真有权限的页。

## 流式 / 加载态
- 作答若流式(SSE / 逐字),渲染区先显「思考中…」骨架,token 到达增量追加;非流式则 loading spinner 到响应返回。
- ⚠️ **流式渲染别每个 token 全量重解析 MD**(O(n²)、长答案越拖越卡):token 先进缓冲,用 `requestAnimationFrame` 节流——每帧最多重渲染一次、把这一帧累积的多个 token 一起 flush;流式期 MD 可能不合法(半截代码块 / 列表),渲染器要容忍不抛、尽量渲染已完整部分。非流式**别假装流式**(逐字假动画只增首字延迟感,是反模式)。
- 别让用户对着空白等——加载态防误以为卡死而重复点(重复点 = 重复计费调用)。

## 历史按用户隔离 + 瘦身
- 对话历史存 localStorage,**key 带 userId**(`kb_history_${userId}`)——各角色 fab 可见按钮、权限不同,串了会让换账号者点到无权限路由。
- 取最近 N 轮(如 5)、每条截断(如 300 字)显示;存太多拖慢渲染也占空间。

## Markdown 渲染:打包不引 CDN + 防 XSS
- LLM 输出 MD 用 `marked` + `DOMPurify`(防 XSS),**打包进 bundle,不引 CDN**——离线 / 内网友好、不依赖外网。
- **别**用 `v-html` / `dangerouslySetInnerHTML` 直渲染未消毒的 LLM 输出。

## 尊重 reduced-motion
入场 / 拖拽反馈 / 加载动效,在 `prefers-reduced-motion: reduce` 时降级(去动画、保留功能)。

## 移动端要点(目标含手机 / WebView 才看)
- **窄屏面板变 bottom-sheet**:<640px 别再用 380px 浮窗,改成贴底的底部抽屉 / 全宽、输入框常驻底栏;否则面板窄得没法看。
- **触屏拖拽防滚冲突**:pointer events 已覆盖触摸,但拖 fab 时要防误触发页面滚动——拖拽阈值(如移动 >4px)判定为拖拽后再 `preventDefault` 锁滚动,未超阈值则当点击展开面板。
- **软键盘遮挡**:键盘弹出会盖住输入框 / fab——监听 `window.visualViewport` 的 resize,键盘起时把面板 / 输入滚进可视区(或把面板高度收到 `visualViewport.height`)。这比监听 `resize` 可靠(后者在很多移动浏览器不触发)。
- **别依赖 hover**:动作按钮等 hover 态在触屏不存在,要点按即可见 / 可触发。
