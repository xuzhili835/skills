# DXF 图纸识别与标注算法：实战教训（FSCC 项目验证）

> 案例底座：汽车冲压焊接件图 FSCC111352.dxf（DXF 2013，约 17MB，模型空间 2.7 万实体），13 轮规则迭代 + 实体级人工验收收敛到 68 个标注。以下每条都有翻车实例背书。

## 第一步永远是结构探查，不要看图猜

写任何识别逻辑前，先用 ezdxf 只读 dump：
- 图层清单 + 每层实体类型计数；
- 各区域包围盒（本例：主视图在 x 490–780 / y 420–790，细节图在顶部，剖视图 R/A/B/C/X 在右/下）；
- 关键实体族的参数分布（半径、颜色、所在层）。

本例实测结构（每张新图都要重新实测，但探查维度不变）：
- 引线 = LEADER 实体（91 条，DIM 层）；球标圈 = CIRCLE（`from` 层，color 6 品红，r=4.5/6.0）；零件几何在 layer `1`；孔 ≈ r1.6 CIRCLE；腰槽端部 = ARC；归并标注 = 多条引线先汇聚到竖直合并线再接球标。

## ⚠️ LEADER 顶点存储方向不统一

- **现象**：假设 `vertices[0]` 是箭头端，一半引线指反。
- **处理**：按几何语义自动判别箭头端（tip）：更贴零件几何采样点、且离球标更远的一端：

```python
def tip_end(vs, geo_pts, balloons):
    a, b = vs[0], vs[-1]
    sa, sb = geo_count(a), geo_count(b)          # R=4.0 邻域内几何点数
    if sa != sb:
        return a if sa > sb else b
    return a if balloon_dist(a) > balloon_dist(b) else b
```

## ⚠️ 几何判定反直觉陷阱清单（每条都真翻过车）

1. **点到 LINE 的距离必须用点到线段距离**，不能用端点距离——贴在线段中段附近的点全被漏掉（曾致局部过滤 kept 0/107）。
2. **ray-segment 交点公式的分母符号**曾写反，表现为射线命中系统性地少一半方向。
3. **多边形包含判定（射线法）前，环点列必须按链序整理并对齐方向**——乱序点列的射线法结果全错（弧升级"缝合闭环"时踩过）。
4. **主方向拟合信直方图，不信内点率扫描**：方向直方图（mod 90° 按段长加权）取峰向+抛物线插值；用内点率扫角会被"斜框恰好卡进直角边界"作弊。精扫窗口 ±3°/±1.5° 都试过，都会被斜框顶到边界，最终完全信直方图。
5. **贴边吸附的边位置取最密集簇的众数均值**，不能对全部射线点取均值——双壁槽的射线点同时落内外两壁，总均值会把框整体带偏（G1 红框外偏的根因）。
6. **局部轨迹带宽**取 `max(90分位+1, 0.6×cap)`——固定带宽遇到偏心末端会剪掉远侧壁。轨迹后做 2 轮邻域中位数平滑去凸刺。
7. **阈值要按实测校准而不是直觉**：双壁壁距可以恰好是 0.499，所以壁厚下限必须 <0.5；外壁可能由两段断线拼成，"单线覆盖率=1.0"的检查会漏掉拼合壁（要支持 ±0.15 容差的断线拼接覆盖）。
8. **拼合/回环用端点网格索引**（eps≈0.8 缝合）+ DFS 回环；框尺寸约束外接对角线（如 [0.5, 250]）排除渲染小点和视图轮廓巨环。

## 拟合必漂移，本体必精确

- **教训**：用射线轨迹拟合出来的圆/矩形/圆角矩形标注，与人工认可的真值总有微小漂移（13 轮迭代后 G1–G8 的 8 个拟合标注仍全被人工删除）。
- **正解**：识别出"目标是什么类型"后，**优先搜索并复制图纸中已有的真实实体**作为标注。本例的 `find_inner_wall_rect`：4 条真实 LINE 围成、包含 tip、边覆盖自适应（rc=min(8, 0.35×短边)）、四边外侧有伴随壁线（同坐标 ±0.15 拼接覆盖 ≥80%）、相对外环面积 ≥12%——命中即复制本体，一次通过人工验收。
- 拟合只作为本体不存在时的兜底（回退存闭合轨迹 poly）。

## ⚠️ 去重聚类判据必须保守

- **现象**：用"环带交叠"做合并，误吞相邻槽的标记（G9 案例）。
- **正解**：合并只认三类保守判据——bbox 包含、中心距 ≤2、**中心深入对方环内（≤min(r)+0.5）**。
- 保留优先级排序：(封闭性优先, 触及档位, 弧最后, 尺寸小)。

## ⚠️ 结构规则 vs 人工意图：用豁免表，不要硬刚规则

- **现象**：按结构规则过滤"同心符号组"，17 个被过滤组里 16 个是用户特意保留的滚花沉孔——结构与噪声完全同构，规则无法区分。
- **正解**：维护人工豁免表（如 `MANUAL_EXEMPT_LEADERS={"25C85","282F6"}`），按**引线 handle** 豁免。注意：豁免条目要交叉核对其目标坐标（282F4 的目标是孔圆不是同组的 609，放错就错杀）。

## 升级链模式（识别兜底的层级设计）

弧目标的标注目标按三级升级，每级失败才走下一级：
1. 所在闭合环（触及 ≤2.3 或包含）——但**内层环资格**要求环外扩 1.0 后必须包住 tip：末端旁边的小盒/细长框即使 gap 很小也不是它的内侧线框（G10 曾被劫持成 4 实体碎片）；
2. 局部射线轨迹（半径 18，两遍过滤）——min 边 ≤4 被折断线截断时走"扁带救援"：从触弧 DFS 找包含 tip 的最小面积缝合闭环，**禁踩长度 ≤1.2 的径向短桥线**（否则内外线角部直连产生月牙环）；
3. 连通域（距 tip ≤8，段数 ≤24 防泄漏）。

尾部语义校验：tail_text 存 JSON，同组类型一致性校验（如 10X 组 = 数量 10 + 组号 G1–G10）。

## 人工标注样图的语义规律（同类图纸直接复用）

- 双壁槽（圆角外壁 + 内壁方框）→ 标**内壁方框**；
- 单壁圆角槽 → 标**跟随槽壁的圆角矩形**；
- 腰形槽 → 标**槽内轮廓闭合线**；
- 圆 → 标触及的圆本身（双箭头触及两个同心圆可各标一圈）。

## 验收闭环（每个图纸识别项目的固定动作）

```
analyze → mark → render + 三查（闭合性/交叠/漏标）
       → 与人工基准逐槽/逐实体比对 → 差异回写阈值/规则/豁免表 → 重复
```

- **配对用几何签名**（类型+中心+尺寸，tol≈1.2），**绝不用 handle**（SaveAs 后重排不可比）。
- 人工批改语义要读懂：人工修正常是"删除错误标注 + 保留正确样例"（v13 案例：删 15 个实体、零新增），先 diff 出"保留=正确样例"再提炼规则。
- 工具链固定四件套：导出基准（DWG→DXF）、签名配对验收、区域渲染 PNG、实体叠加可视化诊断。
- 每轮迭代记录：改了什么阈值、哪些案例由错变对、有没有引入新错（回归）。

## ezdxf 使用注意

- 版本差异实测：1.4.4 的 `ezpath.make_path()` 不支持 LEADER；`.vertices` 两版（1.1.4/1.4.4）都可用。用版本敏感 API 前先 `try` 探测。
- flatten 采样（`p.flattening(distance=0.3)`）再做射线法/距离判定，圆弧类一律先 flatten。
- **区域渲染 PNG 不要手写 LINE/POLYLINE 逐点画（2026-10-21 实测）**：LWPOLYLINE/POLYLINE 的 bulge 圆弧会被画成直弦、ARC/CIRCLE/ELLIPSE/SPLINE 直接缺失、DIMENSION 的尺寸线/箭头在 `*Dnn` 匿名几何块里也不会出现，现象就是"错位、断线、箭头消失"，很容易把标注箭头误判成剖切箭头。正解用 `ezdxf.addons.drawing`：`RenderContext(doc)` + `MatplotlibBackend(ax)` + `Frontend(ctx, out).draw_entities(按窗口 bbox 过滤后的顶层实体)`；后端会展开 INSERT/尺寸块并按弧长 flatten。只过滤顶层实体，**不要手工炸开 INSERT/DIMENSION**（会丢块变换和 `dxf.geometry` 引用）。截图验收先看尺寸箭头在不在——它是"匿名块有没有被渲染"的哨兵。
- 实体几何属性读取全部包 try/except——损坏/异型实体在真实图纸里常见。
- **DXF 中文文字=国标 SHX 大字体**（B-rep3转2 线回写 2026-10-14）：样式必须 `gbenor.shx` + bigfont `gbcbig.shx`；TTF（simsun.ttc）写法数据链路全对（COM 读回 TextString 中文完好、FontFile 字段正确）但 CAD 渲染层不吃、显示 ？??——生成端直接用 SHX 大字体，别拿"读回正常"当验证。
- **$EXTMIN/$EXTMAX 直写 header 会被覆盖**（ezdxf 1.4.4 实测）：saveas→update_extents() 会用布局属性把 header 赋值重置回哨兵；正解 `msp.dxf.extmin/extmax`（布局属性）。"写进去了"要重开文件验证才算数。

## ⚠️ OCC/BRep 几何算法教训（B-rep3转2 剖视图线，2026-10-16 回写）

1. **布尔切观察侧的切盒必须以实体包围盒中心为中心**：曾以剖切面参考点 P1 为中心——P1 可以离零件很远，零件顶端越出盒缘未被切，表现为断面缺 460mm² 剖面线、观察侧材料混入保留半、HLR 多出约 860 个幽灵实体。正解：盒边长取 2×包围盒对角线+10mm，d/t 两向以实体包围盒中心为中心，仅 s∈[−2L,0] 贴剖切面方向不变；修复后保留半体积、断面面积、剖面线总长三者交叉核对全绿。
2. **剖面线填充不走三角化/网格采样**：3转2 的精度根基="面直接投影为线"，符号性/示意性产物也不降精度口径。正解=断面边界取精确实体边、0.05mm 弦高离散、与 45° 线族求交后按半开区间奇偶配对（半开保顶点不重不漏）。交叉核对：剖面线总长 ≈ 断面面积÷间距（实测偏差 <1%）。
3. **细线验收别信视觉模型**：lw0.5 在 3.74px/mm 渲染缩放下是亚像素宽，视觉模型报"完全没有剖面线"还幻觉出不存在的文字。像素级程序检测先行（45° 对角连续性占比、剖面线带 vs 空白对照带密度），目检用高倍放大+加粗重渲染后再喂视觉模型。

## ⚠️ ezdxf 造 DXF 判例与读改写保真(1-236,2026-10-20 回写)

**造合成判例(现画 DXF 断言管线)的坑:**

- TEXT 对齐常量不在 `ezdxf.lldxf.const`(`MIDDLE_CENTER` 报 AttributeError)。锚点判定只看 insert 时,直接 `add_text(s, dxfattribs={"insert": 格心})` 即可,别折腾 set_placement。
- DIMENSION 实体没有 `height`/`char_height` 属性(字高在 dimstyle 里):读文字高一律 try 链兜底,否则半路 AttributeError。
- `add_linear_dim(...)` 不 render 就能被 ezdxf 读出 `dxf.text`(造占位符判例不用渲染几何);未渲染的 DIMENSION 没有匿名块,transform/平移可直接对实体做。
- **表头种子必须落在表 bbox 内**(管线收表条件通常是"种子被表覆盖"):造网格时表头文本必须放第一行带内(格心);放网格上方当"表名"会导致整表建不出来、判例全空——合成判例跑空先查这个。

**跨页缝合(拼版图管线真缺陷,边界判例无意钓出):**

- 上下两页表格 x 完全对齐时,列线按纯坐标一维聚类会并成一根"列线"(范围取并集),经"同列交点全部互连"把两页表格缝成一张(bbox 横跨两页)。修法:聚类除坐标相邻差≤tol 外,加"投影区间与簇内已有线接触(gap≤tol)"判据,区间脱开即拆簇;同列分段画法(gap≈0)不受影响。拼版多页图此前没炸可能只是每页 x 恰好错开的运气——对齐形态要专门造判例。

**读改写保真(验收/另存场景):**

- 实体级保真复制用 `ezdxf.addons.importer.Importer(source_doc, target_doc)` + `import_modelspace()+finalize()`:颜色/线型/文字样式/块原样保留;同名块与样式按名合并——**同源文件的两个副本**(如原文件 vs 只改层的另存文件)几何一致,合并安全;异源文件慎用。Importer 会丢 DIMASSOC 并刷大量警告,`logging.getLogger("ezdxf").setLevel(logging.ERROR)` 静默。
- 整图平移 = 逐实体 `e.transform(Matrix44.translate(dx,dy,dz))`;建图层是 `doc.layers.add(name, color=...)`(Modelspace 没有 add_layer)。
- **验收对照图必须从交付产物生成**(另存文件+JSON),不要"按同样算法重画一遍"——重绘丢颜色/字体/线型,会被一眼打回"和原图差太多";且重绘版验收通过≠交付文件正确(旁路验收陷阱)。可视化技巧:内存副本里把目标图层 color 改 1(红),byLayer 实体自动显红,实体自带色保持原色(符合"移层不改实体数据"口径)。

**跨文档导入 DIMENSION 会丢几何块(ezdxf 设计行为,2026-10-21 补,修正前节一条):**

- 真实 AutoCAD 图纸的 DIMENSION **全都带** `*Dnn` 匿名几何块(可见图形就存在块里);前节"未渲染的 DIMENSION 没有匿名块"仅指 ezdxf 自建未 render 的情形。探针查引用要用 `e.dxf.get("geometry", "")`——`block_name` 是不存在的属性,`.get` 静默回默认值会造成"无匿名块"的误判(亲历)。
- `Importer.import_modelspace()` 导入 DIMENSION 后 geometry 引用**全部变空**:`Dimension.copy()` 故意 `discard("geometry")`(ezdxf 源码注释:新副本不能与原件共享同一几何块),而 Importer 内部正是用 copy() 复制实体。后果:ezdxf 自己读回无恙,AutoCAD 打开报"无有效几何块"、弹修复或加载不出图(500+ 个坏 DIMENSION 实测)。
- 正确姿势(整图平移复制场景):①几何块随行 `imp.import_blocks(块名列表)`;②平移前先给匿名块改名加后缀(`*D76`→`*D76R`,防与底图同名块冲突;`blocks.rename_block` 会同步 INSERT,但 DIMENSION.geometry 要手动改);③`Dimension.transform` 会连带平移几何块内容,不用手动搬块内实体;④DIMENSION 本体**不走 Importer**,手动 `e.copy()`→回填 `dxf.geometry`→`doc.entitydb.add(ne)`→`msp.add_entity(ne)`,其余实体照常 Importer。
- **"ezdxf 打得开"≠"AutoCAD 打得开"**:出文件前必须 `doc.audit()` 断言 errors/fixes 双零,再查 msp 的 INSERT/DIMENSION 引用块是否都在 `doc.blocks`——写进生成器自检,不过拒绝出文件。
- 文件大小突然"省了"也是丢料信号:实体数对但块定义 625→47,说明依赖没跟全(原图大量字节在未直接引用的块定义/样式表里)。

## ⚠️ 剖切符号识别：候选线型不是割切线本身（B-rep3转2，2026-10-21 回写）

- **现象**：A-A 被画成上方棕色 `CONTINUOUS` 直线，两端各有 20 mm 短茎，箭头是块参照 `ASSORTED_DRAFT2` 内的 `SOLID`；旁边 14 mm 下方还有一条红色 `CENTER` 中心线。按候选线型找，会选中红线，报 `arrow_missing`。
- **根因**：候选线型只是入口，不是剖切线的定义；块参照的插入点可能在很远（本例 4817,-4074 / 5162,-4074），箭头几何用绝对坐标写在块内，必须 `virtual_entities()` 展开后才能看到。箭头质心到路径端点可能有 17–28 mm 的短茎偏移，不能用"6 mm 内"直接判。
- **正解**：用"图名 + 两端字母 + 箭头短茎"反推路径：从已知候选线两端找垂直短茎（3–50 mm），短茎外端找 `SOLID` 箭头，再由两个箭头反查与候选线平行、偏移 0.5–50 mm、投影重叠 ≥70% 的连续线。要求两端都闭环，才替换路径。
- **箭头实体不固定**：A-A 的箭头是块参照 `ASSORTED_DRAFT2` 内 `SOLID`；MBK0008 的 W-W/X-X 三套共 6 条，箭头实体是 `LEADER`（引线，CAD 里看着像多段线）；工序图则是 `LEADER` 与 `SOLID` 混用。当前检测器收 `LEADER`、`SOLID` 两类，并用引线离端点最近的顶点当箭头尖；独立 `LWPOLYLINE` 箭头尚未消费，遇到真正的多段线箭头要另补规则。
- **文字扫描查不到 ≠ 图纸没有剖切线**（MBK002U00 青色件，2026-10-21）：T-T、W-W、AA-AA 的字母和箭头是 `LINE/POLYLINE` 笔画，不是 `TEXT/MTEXT`；全实体文字扫描只会看到 A-A，容易误判“不存在”。青色件是原图 42 个实体改色（23 LINE + 19 POLYLINE），不是新画辅助线：T-T 水平 369.907 mm、W-W 竖直 185.754 mm、AA-AA 阶梯四段总长 355.358 mm（转角约 10 mm 空隙），字母为 T/W/A 笔画，箭头为 3 点 V 形折线。当前检测器只出 A-A；T/W/AA 的线都在候选/组件里，但因无文本字母、V 箭头不被 `LEADER/SOLID` 消费、阶梯段 10 mm 空隙大于 1 mm 端点容差而被拒。块展开不解决（这些是顶层实体），需要另做笔画聚类字形、V 形箭头和阶梯段连接。
- **颜色只作预筛**：本例棕色（ACI 32）割切线、红色（ACI 1）中心线、绿色（ACI 3）尺寸箭头确实可分；换图颜色会变，不能写成硬规则。图名文字（如 `SECTION W-W`）可作快速验证锚点，也不能单独当识别规则。
- **验收**：路径端点→短茎→箭头三点闭环；同时输出路径长度、标签距离、箭头数和匹配方式（`matched_by=section_symbol`）；旧 5 图 14/14 回归必须保持。新图族实测：MBK002U00 A-A 344.786 mm/high/2 箭头；MBK0008 W×3+X×3 全 high/各 2 箭头；工序图 6 条（其中 2 条单箭头 `arrow_missing` 待核）；成品图 0。

## ⚠️ 剖切线路径搜索的真实边界（2026-10-21 实现更新）

- **真实顺序是“筛选 → 建组件 → 判定 → 路径还原”**：候选线型 → `build_components`（同组端点并查集，同时按整条组件长度筛）→ `pair_sections` / 宽口径标签+箭头验收 → `chain_path` 路径还原。长度门槛在建组件时就生效；小于门槛的组件根本不会进入组件列表，不能讲成“种子没接上”。种子生长发生在判定成立之后。
- **主路径仍是并查集 + 贪心，不是全图 DFS/BFS**：候选段按线型组分组建端点并查集，同组端点 ≤1 mm 合并成组件；`chain_path` 的起点是第一个度 ≤1 的自由端，若没有自由端才取第 0 段，之后每次接最近端点。没有“尝试—失败—回溯”。动画里的种子应解释为“自由端”，不能按旁边的字母命名种子；字母只是恰好靠近。
- **阶梯剖是局部桥接，不是全图图搜索**：AA-AA 的“10 mm 空隙”实际是 6 段 10 mm 的 `BYLAYER` 连续连接线，不在候选线型表里，所以 1 mm 并查集把整条拆开。做法是从一端已看到笔画标签的组件出发，沿 1 mm 端点吸附短连续线，再用 BFS 最短段数找两端路径、裁掉吸附进来的旁支（输出 `bridge_branches_ignored` 警告）。BFS 只服务这条桥接路径，不改变主路径的并查集/贪心性质。
- **阈值已改为标签字高自适应（2026-10-21 实现）**：`MIN_PATH_LENGTH_MM=18`、`ENDPOINT_TOLERANCE_MM=1` 只保留为字高缺失时的回退值。正常路径用 `label_unit`（正字高 75 分位）换算：最短组件 `4×字高`（下限 6 mm）、端点容差 `0.22×字高`（下限 0.4 mm）、标签距离 `8×字高`（下限 10 mm）、同字母跨度 `90×字高`（下限 100 mm）。旧图 4.41 mm 字高对应 17.65 mm / 0.97 mm，实测旧 5 图 14/14、MBK 5 条、工序图 6 条均未变；合成变换 ×2、×0.5、旋转 90°、0.3 mm 抖动均检出同一组 7 个字母。字高缺失（0.0）时退回绝对值，仍需补另一种基准。
- **图幅清理不能用“识别到的图框”当唯一保留集**（2026-10-21 事故）：`extract_sheets.py` 旧逻辑一旦找到图框块，只保留未打叉图框内的实体，其余全删。实测一张总成图 `frames_found=13 / frames_active=4`，被删 123,598 个实体，图框外的人工黄色剖切线（46 个 ACI 51 实体）整片消失；用户明确说那片只有红框、没有红叉、旁边写着“最新图使用中”。现在默认 `mode=delete_obsolete`，只删红叉框内的实体；`keep_frames` 必须显式传。安全版实测保留 52,033 个实体、46 个黄色实体全部保留。任何“按识别到的框保留”的清洗，都要先证明框集覆盖了所有有效图幅和框外批注。
- **文字优先，矢量只做降级**：严格/图名线型/宽口径三路文字、块参照、LEADER/SOLID 路径先跑；只有组件未被接受、且两端 25 mm 内没有文字标签时才走矢量回退。矢量字形识别失败就不猜，不覆盖文字结果。
- **人工彩色批注不能直接当候选**（2026-10-21 实测）：用户用 ACI 51 手绘的 A/B 剖切线是 39 段 `LWPOLYLINE`（`Continuous`、层 0、约 10 mm 空隙）+ 4 个箭头 `HATCH` + 3 个 `MTEXT`。当前候选线型表不收 `Continuous`；即使按颜色放行，10 mm 空隙大于 1 mm 端点容差，并成 1 个组件后出现 18 个端点（分支），`chain_path` 的“自由端+贪心”只走其中一条；标签是 A、B、B，只有一个 A，A-A 无法成对。结论：手绘批注只能用于人工复核对照，不能直接当算法正例；要支持需单独做“批注颜色模式 + 10 mm 桥接 + 全局路径选择”，不能只放宽一个阈值。
- **字形最小实现只命名 A/T/W**：按笔画拓扑识别（先把同笔拆开的共线段合并；不要求水平/竖直，A 随视图旋转 90° 仍读 A）；V 形箭头按两臂夹角 + 角平分线定向；双字母按同一行相邻字形拼 AA。Z/其他字母暂不命名；要扩 A-Z/0-9，必须用真实样本建统一模板/拓扑库，不能按句柄、颜色或样本字母清单写死。
- **方框/气球标签和尺寸箭头是强负例**：F3a-F3b 的 Y1/Z 方框标签、尺寸箭头、中心线，单独裁窗跑检测应为 0 条（实测 0）。当前靠“两端标签句柄必须互斥 + 两端都要字形和箭头”挡掉短窗口复用；显式方框/气球、带数字、DATUM/DIM 层过滤仍未加，`relaxed_arrow` 单箭头 medium 的残余风险仍在。
- **验收口径**：旧 5 图 14/14；MBK0008 W×3/X×3=6；工序图 A×3/B×3=6（其中 2 条 A 为单箭头 `arrow_missing` medium）；成品图 0；青色标注件 9（A×3/AA×2/T×2/W×2，三张视图各一套）；清理正常图幅 5（A,A,AA,T,W）；F3a-F3b 负例 0。

**"未用色"选了也别信 ACI 号(ezdxf ACI 色表陷阱,2026-10-22):**

- ACI 250-255 是 1-249 的**替代色/灰阶表**,RGB 可能与主色完全相同:实测 ACI 170 的 RGB=(0,0,255),与 ACI 5 逐位相同。只判"该色号是否被用过"会选出与原图同色,图上根本分不出。
- 正确选色:候选色号未用过 **且 RGB 与所有在用色距离²≥4000**,再加亮度下限(0.2126R+0.7152G+0.0722B ≥0.45)保证黑底醒目;若图上主色集中在某色相(如整页绿),要按**高频色权重**选"与高频色最小距离最大"的,而不是"与所有颜色最小距离最大"(后者会被低频冷门色稀释,选出偏暗的深蓝)。

**表格重复检出的两种形态(聚类类管线通用):**

- 同一标题栏被不同种子词/窗口各长出一套网格:①近乎重合(IoU≈0.7);②小框被大框整体包含(包含度>0.9 但 IoU 只有 0.17,IoU 单判据漏掉)。去重判据必须两条都收:`IoU>0.5 或 交集/小框面积>0.85`,保留 bbox 面积大者。
- 实测真实图纸 186 个"标题栏"里有 69 个是重复检出,合并后 117;表数/行数/关联数零漂移——说明去重只影响展示与抗干扰计数,不动主链路。

**语义层过滤要留档(占位符/关键词类识别的通用做法):**

- 几何/形态识别出的候选,若再按业务语义收紧(例:占位符的变量必须被规格表引用),**不要直接丢弃**:输出里保留 `unmatched` 清单(值、来源、坐标、过滤原因),并在验收图上说明过滤了多少。否则事后无法区分"本来没有"和"被我筛掉了",也无法回滚口径。
- 收紧前先量化噪声构成再定规则:本例 779 条候选里 704 条是 A4 图框分区标记 A/B/C/D/E(89% 距页块边界<3mm)、REVISIONS 版本号 X1、表头词 QTY/MM——有这组实证,规则才不是拍脑袋。
