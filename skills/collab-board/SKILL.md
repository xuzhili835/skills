# 多AI协作开桌(协作板模式)

设计立场(先读,三条贯穿始终):
- **基建按项目立,不按 AI 立**。生成的是项目文件,不是 N 份角色提示词——窗口是易耗品,文件是资产。
- **分工长出来,不预设**。窗口上岗自己起线标领活;某条线干熟了才把惯例写进板子,记事实不记设想。
- **派单权在用户**。"用户在哪个窗说话,就是给那个窗的直接指令"——协作板只负责记帐和防撞,不负责指挥。

## 何时不用
- 单窗口能干完的活:不开桌。
- 项目只有零星两三次会话:在 AGENTS.md 写两行分工即可,不建协作板。
- 已有协作基建(AGENTS.md 协作节/协作板/决策记录):**只补缺,现有内容一字不动,不重建**。

## 开桌四步
1. **项目根 `AGENTS.md`**:无 → 按 references/templates.md §A 生成;有 → 只把缺的协作节追加(既有内容一字不动)。生成的文件保持精简,只放协作机制与用户点名的红线,业务事实进协作板,不写这里。
2. **项目根 `CLAUDE.md`**:无 → 只写一行 `@AGENTS.md`(Claude Code 读 CLAUDE.md,@import 自动引入 AGENTS.md 全文;**严禁整份拷贝**,两份必漂移)。已有且不是指针的:不动,知会用户"建议合并为指针、内容移入 AGENTS.md",等点头再动。
3. **`AI协作/协作板.md` + `AI协作/复盘.md`**:按 §C/§D 生成;已有只补缺。
4. **给用户开桌清单**:开 N 个窗(任意工具都行),每窗贴同一句启动语(§E)。加窗口不需要再生成任何东西——基建只有这一套。

## 可选模块(开桌时问用户装不装,装了才写进 AGENTS.md)
- **台账纪律**(模板§F):项目有判卷标准/冻结集/关键配置时装——改动先登记依据、版本递增、旧版封存、前后回归留档。百景大赛"标注静默漂移"事故的直接护栏。
- **工作日志供料**(模板§G.2):周报型工作区装,单一主源+四类过滤(★成果/卡点/真踩坑/跨线通报)。
- **git 共树纪律**(模板§G.3):代码项目装;没有仓库就先 git init 再装——"不是 git 仓库"是要装的理由,不是不装的理由。
- **自动化唤醒层**(见专节):多窗项目按阶段自动识别启用——早期长程迭代冲刺(整包任务成批/闭环未跑通/有截止日)启用,后期精修(小颗粒修补为主)不启用;装了才把对应惯例写进 AGENTS.md。
- 用户开口径里已点名的红线(如"审查只读"),不问,直接写进 AGENTS.md 固定红线节。

## 知识放哪(三路由,写进 AGENTS.md 让所有窗口继承)

| 内容类型 | 去处 |
|---|---|
| 运行状态:谁在干什么、卡点、待办 | 协作板 |
| 恒定约束与裁决:纪律、口径、红线、定案 | AGENTS.md / 决策记录 |
| 经验教训与方法论:踩坑、用户偏好、怎么干才对 | 本工具自己的项目记忆,鼓励写,照常写 |
| 用户明确的项目级新规则 | AGENTS.md(当次写入、查重压缩;见"规则收口") |

唯一硬禁令:**运行状态和项目裁决不得只存在 memory 里**——memory 是各工具私有仓库,跨工具看不见,换目录开还会断键。三条路由是分工不是取舍,禁令不拦 memory 正常记录教训。

正反例(按这个口径执行):
- ✓ 踩坑"探针必须 UTF-8 文件" → 写 memory(下次会话自动召回)
- ✓ 定案"锥度过渡算独立 Cone 实例" → 写决策记录(所有工具可见)
- ✓ "I12 进行中,卡在等规范" → 写协作板
- ✗ 把"I12 进行中"只写进 memory → 其他工具的窗口永远看不见,协作静默断裂

## 规则收口(AGENTS.md 自更新)

- 开桌时就把"规则收口"三~四条写进 AGENTS.md(模板 §A),不要等用户下次提醒。
- **必须写入的恒定约束之一(用户 11-04 定):在线登记"正在干"是瞬态状态字段**——开工写"这一件+卡点"、**办结即抹掉**、空着=空闲属正常、办结只进回执区不在此复述、**不归档**、单格超 150 字可清。模板 §A(AGENTS.md 协作节)与 §C(协作板表头)已内置此条;**目标项目若"只补缺"而缺此条(存量项目常见),须补上**。
- 运行中用户明确说"以后都这样 / 写进 AGENTS.md / 这是全局规则 / 记住这个规矩"时:当前窗口当次写入 AGENTS.md,并在当周工作日志或协作板回执区留一句【通报】,让其他窗口看见。
- 只收恒定约束(纪律/口径/红线/定案/用户点名的长期偏好)。运行状态、一次性任务、过程记录不进 AGENTS.md——走协作板/日志。用户只是描述一次做法,不触发。
- 写入前查重:已有同义条合并改写,不新增重复条;单条压到 1~2 行可执行约束,不整段贴对话原话。
- 防膨胀:AGENTS.md 接近 200 行(或项目自定上限)时,先合并同主题、删过期条;仍超就把细节移到项目文档,AGENTS.md 只留约束+指针。
- 改完按项目纪律留【通报】;AGENTS.md 不另存副本,避免多份漂移。

## 线与分工
- 不写角色书。新窗口贴启动语上岗:自己起线标、登在线表、看收件箱领活;没活就问用户。
- **收件箱是跨线协调专用,不是干活流水账**:用户会话即办直派的活直接干,不写条目,顺手把自己在线登记的"正在干"改一下即可。只写三种条目:①请别的线行动(委托/请求);②改动预警(会影响别的线,如机制改布局影响美术产出);③卡点求助。回执只用于收件箱条目的办结闭环。
- **通报写法与归档(防板胀,人人每次读板都在付成本)**:恒定要求一律进 AGENTS.md/决策记录,板上通报只留一行指针("某规矩已入 AGENTS§节,日期"),不承载规矩全文——这样归档通报零风险,规矩不丢。影响开发口径的预警走条目生命周期:各线开工回执写"已按 vX 对齐"即已读凭证,全员对齐后删条归档;重大预警可加显式已读标记(条目下 `- [线标 已读 日期]`),最后一个读的负责删条。纯知会通报由统筹线例行归档——**归档权集中**,其他线不归档是分工不是不敢。
- 线惯例后置:某条线范围稳定后,由主窗把惯例写进协作板"线惯例"节,三五行一条。
- 换手:用户直接在另一个窗说(会话即办);接活的把板上条目线标改成自己(或标"代")。
- 常见分工仅参考、不预设:游戏=机制/美术/审查;软件=按模块+审查;文档=写作/校对。**审查类窗口固定只读**——用户点名设立时,红线写进 AGENTS.md 固定红线节。

## 主窗(用户指定统筹窗口时)
职责=服务,不是指挥:汇总各线状态、清扫流水账(含已消费通报例行移 `AI协作/归档/`)、协作板单文件超 200 行移 `AI协作/归档/`、收尾归档、代办决策提请、加人/收线时维护在线表与决策记录。主窗不替用户派活,不写功能代码(用户明示除外)。

## 自动化唤醒层(按项目阶段自动识别,非默认)

协作板只解决信息共享,不解决唤醒——窗口干完一轮就休眠,板上新条目它"看不见",除非用户去敲。要不要补唤醒层**按阶段自动判断:立板时判一次,主窗(统筹线)每次看板复核**,阶段反转提请用户开/停(停用若获用户预授权则自动停,见"停用动作"):

- **启用特征(早期长程迭代)**:收件箱 ≥2 条开发类整包任务在途/待领;核心闭环未跑通、模块成批待建;有冲刺截止日(答辩/交付/上线)。
- **不启用特征(后期精修)**:核心已跑通,任务以小颗粒修补为主(bug/文案/样式/文档),收件箱日均流量低——人工敲窗足够,自动化白耗额度。
- **停用动作(自动取消闭环)**:启用时就向用户要一句授权——"冲刺/迭代结束后要不要自动停常驻任务";停用判据(满足其一):记录的截止日已过(+1 天缓冲)/**阶段停滞信号**=收件箱空或只剩小颗粒条目+全员登记空闲+最近 12 小时无新开发类交付(用时长代理,别写"连续 N 次"——定时运行无状态,数不了次数)/用户明说转入精修。停止条件**写进常驻任务的提示词**(第⓪步:每次触发先复核判据),命中即自暂停(CronPauseSelf 类机制,可恢复)+板上【通报】;定时运行不能自删,彻底删除由用户或交互会话执行;各线退避链靠命中判据后"不续挂"自然终止,无需清理。**收线宣告自动化**:统筹线判据命中先在板上写一行【宣告】收线/转精修(注明触发证据),宣告一次全员熄火——各线链下次检查判停时自动不续挂、登记"已收线",用户无需逐线通知;用户宣告仅是兜底不是必经。

启用分三层,**前提=当前工具支持定时/后台自动化**(如 ZCode 定时任务);不支持的工具退回人工唤醒,可选配文件监视脚本弹通知兜底:
1. **收工自挂检查链**(全员惯例,写进项目 AGENTS.md;原"退避链"15→30→30 已废——11-04 用户裁决:15 分钟档在长程任务下触发过频、干扰用户插入指令,改为**固定 30 分钟单档**):办结条目后自挂一次性看板检查(30 分钟后);空闲续挂同档(恒 30 分钟);领到活不升档不降档,仍 30 分钟档;**退出靠判停不靠时长**——本机制本就服务冲刺/长程迭代,空闲拉长即阶段收尾信号,走判停退出而非"越睡越沉"。每次检查次序=**先判停**(命中自停条件/统筹线宣告收线→不续挂,登记"已收线"结束)→**再续命**(先续挂下一次防断链;23~8 点夜间段直接挂次日 8 点档)→**后干活**(单次只领一条)。
2. **统筹线常驻 cron**:每 30~60 分钟读板——处理自己名下事项;发现"某线空闲而板上有其活/前置已满足"→告知用户去敲哪个窗;文档通报查漏;板超 200 行归档。夜间降频,无活即退。
3. **各线常驻低频 cron**(可选,经用户批准):同 1 的判断固定周期跑,冲刺抢进度用。

**平台机制约束(挂链前先实测,别照搬设计;ZCode 11-04 实测口径)**:①每会话限挂 1 条自动化,被定时任务触发过的会话会被该任务占槽;②已完结的一次性任务**不自动腾槽**,仍占会话名额;③定时运行内不能直接新建,须先删本会话已完结旧任务再建(CronDelete 旧跳→CronCreate 新跳,实测可跑通)。由此两种挂链形态:**A. 常驻 recurring+判停内置**(复刻统筹线模式,最稳——请用户新开会话挂一次,判停写进提示词第⓪步,命中 CronPauseSelf);**B. 一次性自续挂链**(退避档位灵活,每跳=先删旧跳再建新跳)。探测不了或删除受限→一律退回 A。

**预热启动**:设计文档未就绪也可先开线——各线领不到活照常挂链待命,不报错不干等;主窗补完基准文档、往板上派条目后,空闲链一个档位内(≤30 分钟)自动捡单,用户无需转达。冷启动顺序=主窗开桌立基建→出基准文档骨架→用户开 N 窗贴启动语(各线挂链预热)→主窗写文档派活→全员自动开工。

防跑飞铁律(逐条写进每个定时任务提示词):单次只领一条;无活即退、无事不做任何写操作;领活走板上协议防抢占;定时运行无会话记忆,提示词自带上岗上下文(靠 AGENTS.md+协作板)。硬边界:统筹线无法跨窗口打字——别的窗启动干活只能靠它自挂的定时任务或用户去敲。

收工自挂**统一话术**(给用户贴各窗,避免各线自拟措辞走样;定时任务标题起短名,防触发时改写窗口标题):「读 AGENTS.md 自动唤醒规则:从现在起你维持检查链可达——每办结一个协作板条目或每次检查后空闲,都给自己挂一次性看板检查(挂新跳前先删本会话已完结的上一跳腾槽——每会话限一条自动化、已完结不自动腾槽;删不动就请用户新开会话挂常驻 recurring 版,判停写进提示词):档位固定 30 分钟(办结后挂 30 分钟,空闲续挂 30 分钟,领到活也 30 分钟,不退避);退出靠判停不靠时长。每次检查次序:先判停(命中 AGENTS 自停条件或板上宣告收线→不续挂,登记'已收线'结束)→再续命(先续挂下一次;夜间 23~8 点不干活,直接挂次日 8 点档)→后干活(单条);一切以 AGENTS 最新口径为准。」

## 收线
阶段结束时主窗把"当前阶段、各线下场、遗留事项"写进决策记录置顶——下个会话读板即热启动。

## 模板
全部在 references/templates.md:A=AGENTS.md 协作节(含收件箱生命周期/卡点写法/分歧处理链的完整操作规程)、B=CLAUDE.md 指针、C=协作板、D=决策记录、E=窗口启动语、F=台账(可选)、G=可选模块清单。
