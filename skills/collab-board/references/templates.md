# 模板(拷进项目时替换〈〉占位;小节按需删留,保持精简)

## A. AGENTS.md(项目根;无此文件则整份生成,有则只追加缺的节)

```markdown
# 项目须知(〈项目名〉工作区)

> 本文件是项目级公共约束:在本目录开的每个对话自动加载。改动它=改动所有窗口的公共约束,改前知会其他在线窗口。

## 协作模式
- 本目录常有多个 AI 窗口同时干活。窗口身份不预设,谁领了什么活看协作板。
- 收件箱是跨线协调专用,不是干活流水账。用户会话即办直派的活不进收件箱,直接干,顺手更新在线登记"正在干"。
- 只写三种条目:①请别的线行动(委托/请求);②改动预警(会影响别的线,如机制改布局影响美术产出);③卡点求助。纯知会不进收件箱,写回执区标(通报)。回执只用于收件箱条目的办结闭环。
- 收件箱条目生命周期:①提出——写 `- I编号 【待领】【事项】一句说明(提出:线标, 日期)`,编号顺着板上最大号+1;②接活——把【待领】改成【自己线标】并打 →,同步更新在线登记里自己那行;③办结——**删条**,回执区追加一行:`日期 线标 I编号 结论/产出路径`。长回执内容写进产出文档,条目下不留回执链(不删条=收件箱膨胀)。
- 卡点条目必须写明"在等谁给什么"。正例:`【审查】【冻结集复核】卡点=等机制线出新真值(产出:路径)`;反例:`【审查】待命,无事可做`(过程流水,不许写)。
- 一条条目只说一件事;有进展改原条、只留最终结论,不另起一行。
- 写板前必须重读最新版;一次只增删自己名下条目;冲突以先写入者为准,后写入者重放。
- 用户在哪个窗说话,就是给那个窗的直接指令(会话即办);活换手时把板上条目线标改掉或标"代"。
- 分歧处理链:窗口间意见不合,不在板上对吵——各写一句理由进 `AI协作/复盘.md` 提请(共用一个 D编号),等用户裁决,裁决结果回写。
- 项目级大决定(方案/结构/对外承诺/判卷标准)不自行拍板:写决策记录提请,等用户裁决。
- 含数字的结论必须带来源链路:数据哪来 → 怎么算 → 为什么是这个值。
- 固定红线:〈用户点名填。示例:审查窗口只读不改;冻结物/判卷标准改动走台账+版本号;不可逆动作(删除/推送/对外)等用户明令〉

## 知识放哪(三路由)
- 运行状态(谁在干什么/卡点/待办)→ 协作板。
- 恒定约束与裁决(纪律/口径/红线/定案)→ 本文件或 `AI协作/复盘.md`。
- 经验教训与方法论 → 写进本工具自己的项目记忆,鼓励写。
- 唯一硬禁令:运行状态和项目裁决不得只存在 memory 里(其他工具的窗口看不见,换目录断键)。三条路由是分工不是取舍。
```

```markdown
# 〈对象〉改动台账

> 任何对〈对象〉的修改必须先在此登记依据再动手;版本号递增,旧版封存留档;禁静默修改。改动前后各跑一次回归并留对比。
```

## G. 可选模块清单(开桌时问用户装不装,装了才写进 AGENTS.md)

1. **台账纪律**(§F):有判卷标准/冻结集/关键配置的项目装——改动先登记依据、版本递增、旧版封存、前后回归留档。
2. **工作日志供料**(周报型工作区装):日志主源唯一(当周一个文件,放指定目录),各线一行一事带线标;只记四类——★成果 / 卡点 / 真踩坑(一行教训) / 跨线通报;不记签到、读板、待命、过程流水;随手写不攒;同主题改条不追加;主窗有清扫扩权。
3. **git 共树纪律**(代码项目装;没有仓库先 git init 再装):多窗口共用工作树,按 hunk 拆分提交、单主题单提交、不加 Co-Authored-By;push/合并等外发动作等用户明令;他人的实验文件不碰。
