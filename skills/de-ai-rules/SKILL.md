# 去 AI 味（工程文档版）

应用时机：初稿完成后独立过一遍，逐段对照；**不边写边改**，边写边改容易矫枉过正，也会把真正要说的东西删没。

两条底线：不靠口语化换人味（工程文档保持书面语，禁"咱们/说白了"式假口语）；只换词不删结构等于没改。

## 工作方式

1. 先把全文按段落切块，**逐块过下面五条测试**；表格 cell、图注、页脚、代码里的说明文同样要过——图注最短，最容易被当成"不算文案"跳过。
2. 命中就给出「原句 → 改后」对照；改后必须仍然信息完整，宁可换词不删信息，只有测试 2（够用即停）允许整段删。
3. 交付时只报改动清单（哪一段、原来什么味、改成什么），不复述整篇文档。
4. 用户已经手改过的句子一字不动——那是他自己的取舍。

## 七条结构性测试

### 1. 读者独立性测试 —— 管"谁问你了"

假设读者只看文档、没参与过我们的对话，每句话还要能独立成立。

- **判据：这句话在给读者信息，还是在回应一个没人问的问题？**
- 对话残渣（回应讨论中某个质疑、替假想反对者辩护）→ 删。
- **选型理由不算残渣**：做法存在有限几种方式、读者会关心为什么选这种时，理由对读者有用——保留，但改写成正面陈述：做了什么 + 为什么适配当前条件。禁用"而非 X / 暂不采用 X / 之所以 Y"这类回应框架。
  - 反例："采用几何特征加决策树，暂不采用深度学习，原因是样本少易过拟合"——没人质疑却被辩护，读者莫名其妙。
  - 正例："选型用几何特征加决策树。当前标注样本 17 件，这个量级规则和浅层树够用，结果能逐条人工核对。"
- **自证与常识线**：「不是写死的」「并非拼凑」「绝不引入人工干预」这类**否认式自证**，是在回答一个没人问的质疑，与"暂不采用 X"同罪，但多一层误判——它常被自认为"表现细心"。判决三问：
  ①**怀疑在场吗**：读者此刻真的在怀疑这个吗？还是只有训练数据里的常见差评（"演示数据是假的""是不是硬编码"）？没在场→删。
  ②**过不过常识线**：这个疑虑属于读者群体的默认预期吗（答辩默认演示的是真系统、客户默认账目不敢造假）？在默认预期内→删，连正面重述都多余，它读起来像心虚。
  ③**疑虑真实在场时**不删事实，改正面承载+给验法："四项统计实时聚合，任意一步操作后数字即变"——否认的意思由事实自带，否认词一个不留；能当场演/当场核的注明"可当场验证"。
- **细心与奇怪的边界**：主动写进来的细节，能回答读者的一个真实疑问、或带可核验的具体物（文件名、日期、"可当场核对"），是细心，保留；回答不了任何疑问、读者也无从验证的，是噪音。判据：删掉这句，读者会不会以为自己漏了什么？不会→删。
- **别误杀主动披露**："召回偏低，靠人工复核兜底""负样本仅 20 例，是小样本口径"披露的是**对自己不利的短板**，是诚实信号；否认式自证否认的是**对自己的质疑**，两者方向相反。如实写短板正当，防没影的枪多余。

### 2. 够用即停 —— 管升华与闭环

说清就停。删：句尾意义补语（"奠定了坚实基础""具有良好可扩展性"）、短文档里的总结段、展望段。结尾停在最后一个事实上。

### 3. 节奏自然 —— 管机械感

- 具体优先于抽象：数字、阈值、文件名、字段名，好过"少量 / 适当 / 相关"。
- 段落长短允许不均，一句话的段落可以有，表格与叙述混排。
- 警惕三连排比、等长句、每段固定句数的节奏。

### 4. 框架词浓度 —— 管术语口号化

把一个抽象词造成全文主语反复锤，是典型的 AI 指纹。词本身往往没错（"断言"在代码语境是本义词），错在浓度和比喻链。

- **判据：同一个框架词在一份文档里当主语出现超过两三次，或拖着一串配套比喻（"当裁判""降级为证据"），就有 AI 味。** 独立出现的对抗/军事隐喻（零误伤/按类清剿）同判——见词表。
- 改法：对外文档首次出现定义一次，之后换本义词轮换（判定规则 / 判定条件 / 满足…才判为）；比喻最多留一次；代码注释、内部讨论不受限。
- 同一判据也管公文体词（台账 / 沉淀 / 拉通 / 对齐）：词后面指得出**读者也知道**的具体东西才保留。指不出、或只是自己电脑里的内部文件（曾把自建的 `标签台账.csv` 写进周报当"台账"——读者没见过这份文件），或只为显得严谨（"建立台账机制""形成管理闭环"），就删或换具体名词。
- 实例："三条结构断言，命中一条判该类" → "依次检查三类结构特征：贯穿孔道、齿阵列、板形大平面，命中一条判该类"；"数字门槛只作为断言的参数" → "数字门槛只是规则的参数"。

### 5. 口语黑话与生造压缩 —— 管"聊天的词进了文档"

书面语底线是双向的：既禁"咱们/说白了"式假口语，也禁**聊出来的黑话**和**为省字生造的压缩词**。两问判决：

- **正式邮件测试**：这个词，工程师会在发给客户的正式邮件里写吗？不会→换。"渲染层不吃"→"渲染层不显示"；"踩坑"→"遇到的问题"。
- **展开测试**：两三个字的自造压缩，展开成白话意思不变且更清楚 → 展开。"重产"→"重新生成"；"只滤"→"只过滤"。
- **真行业词不误杀**：对账、落盘、回读、消隐、合板这类读者群体（工程师）通行的行话是可信度，不是 AI 味。分界＝**读者群体是否通行**，不是"听起来随意"；拿不准给全称。
- 实例（复盘 PPT 图注漏网）："TTF 写法数据正确但渲染层不吃，换字体重产即恢复" → "TTF 字体的文字数据正确，但 CAD 渲染层不显示；改用国标 SHX 大字体重新生成后恢复正常"。

### 6. 动补结构 —— 管"机器模仿口语"（2026-11-12 补）

书面语一般不用动补结构：动词后面再挂一个表示结果或方向的补语（"得/到/住/上/出/开/起来/下去"）。这类说法在口语里自然，写进论文、方案或评审材料会显得随意，也很容易被判成机器模仿口语。

- **判据（按结构判，不按词表判）**：把这个动词短语拆开看，后半截是不是在补充"结果"或"方向"？是→不属于书面语，改写。改法有两条：换成及物书面动词，或改成"可＋动词"。
- 举例（只作示范，不是白名单，换一个词同样按上面的判据处理）：查得到→可检索；翻出来→调取；压住→控制在…范围内；接上→衔接；跑通→完成联调；兜底→由…承担。
- **例外**：已经凝固成实义词的不算动补，如"得到""达到""看到""看作"，不改。
- **反向陷阱**：为了"像人"而去堆"的、了、到"或掺口水话，会把文本推成"机器模仿口语"，比原文更像 AI。降重靠句式重组与具体事实，不靠虚词密度。
- **长句不等于从句套娃**：一个长句可以连三个分句，但分号不超过两个，超过就该断开，否则读者断不开。

### 7. 列举与举例 —— 管清单化与空引用（2026-11-12 补）

正文里把内容切成清单，是最容易被认出来的机器写法："存在三方面问题：一是…二是…三是…""功能分八块：1.…2.…"。

- **正文不切清单**：改成连续叙述，几条内容用逗号、分号串在同一句里；确实要列，只限两种场合——模板本身要求逐条填写的表格，以及参数、字段、接口这类本来就该列成表的对象。
- **举例直接给对象**："比如""例如""研究表明""据调查"后面跟的常是没出处的空话，换成具体对象，或给出数据与来源。
- 判据：删掉"比如"两个字，句子还成立吗？不成立说明这个例子只是装饰。

## 词表（出现即改写）

- **回应式句式**：不是…而是 / 并非…而是 / 与其说…不如说 / 否认式自证开场（"不是写死的""并非拼凑"——见测试 1 自证条，判决三问）
- **路标词**：此外 / 首先 / 其次 / 最后 / 另外 / 因此 / 段首"同时" / 值得注意的是 / 需要指出的是 / 总而言之 / 综上所述
- **套话大词**：赋能 / 颗粒度 / 闭环 / 抓手
- **对抗、军事隐喻**：误伤（→未误删正常线条）/ 清剿（→逐类排查）/ 清零 / 拍板（→待选定）/ 拿下 —— 隐喻换事实陈述：谁没被删、什么待定、谁定的。内部过程词同理过展开测试（"无未认领"→"全部完成映射，无遗漏"）。
- **内部黑话与自造词**：指纹（边指纹→边集 / 回归比对）/ 翻摊（→展开至纸面）/ 白删（→多删）/ 砍过头（→删多了）/ 归因（→原因定位）/ 链路（→删或"流程"）/ 对方侧（→工程师侧）/ 对账（工程师语境是本义行话不杀；项目经理周报、教学归档读者不通行→"与本方产物核对"）——判据同正式邮件测试：没参与我们对话的读者（项目经理/面试官）看不懂的词，展开或换本义词。
- **升华补语**：奠定基础 / 保驾护航 / 迈上新台阶 / 有力支撑
- **口语黑话进书面**：不吃（→不支持 / 不显示）/ 踩坑（→遇到的问题）/ 拉齐（→统一）
- **生造压缩**：重产（→重新生成）/ 只滤（→只过滤）——两三字自造压缩一律过展开测试
- 动补结构（动词＋结果/方向补语）：不逐词记忆，按测试 6 的结构判据处理；凝固成实义的「得到/达到/看作」不改

注意区分本义词：几何"闭合环""闭环锯齿""投影与原图对齐"是术语，不改。

## 改写示例

1. 选型辩护 → 正面适配陈述（见测试 1 正反例）。
2. "铲齿的识别难点不是外形复杂，而是竖线数量多" → "铲齿侧壁有一条条竖直窄槽，单件几十到上百条，明显多于另两类"（直接给事实，不需要对照壳）。
3. 结尾"该方案为后续算子开发奠定了基础" → 删，停在上一个事实上。
4. "TTF 写法数据正确但渲染层不吃，换字体重产即恢复" → "TTF 字体的文字数据正确，但 CAD 渲染层不显示；改用国标 SHX 大字体重新生成后恢复正常"（口语黑话＋生造压缩，见测试 5）。
5. "本次共处理 46 个候选组件，其中 7 个予以采纳" → "46 个候选组件里采纳 7 个，其余 39 个逐条写明理由"（公文体"予以"换口语序，信息不减）。

## 边界

用户自带「降重 / 去 AI 味」规则清单时：其中「多加虚词」「多用口水话」「尽量不用句号」这类与学术规范冲突的条目，说明理由后不执行；术语、数字、事实一律不动。

查重口径与文风是两件事：连续 N 字重复、字数波动属于查重工具的判据，不是写得好不好的标准；为降重做同义替换容易把话改拧，更有效的办法是补进只有这份设计才有的具体事实（数量、阈值、字段名、文件名）。

- 营销文案、宣传语、落地页、公众号、视频脚本：走 `copy-taste`，那套讲槽位、金句、诗意模式，与本 skill 不同。
- 界面版式与视觉：走 `frontend-design`。
- 用户明确要求"保留某种官方措辞/模板固定句式"时，模板句优先，本 skill 只改模板之外的正文。
