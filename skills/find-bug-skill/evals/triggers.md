# 触发评测集（triggers）

用途：检验技能 description 是否在正确的时机点亮、错误的时机闭嘴。换 description 措辞后，用本清单在新会话里逐条人工验证（粘贴 query → 观察是否激活本技能）。首次整理于 v1.0.0。

## 应触发（正例）

| # | 用户说 | 判定要点 |
|---|---|---|
| 1 | 帮我找 bug | 核心触发语 |
| 2 | 独立测一轮这个系统 | 托管姿态 + 全面性 |
| 3 | 像上次那样再全面测一遍 | 引用历史轮次仍应命中 |
| 4 | 验证这轮改动有没有引入新问题 | 回归型意图 |
| 5 | 我去睡了，你自己测，有问题别改先记下来 | 托管 + 只测不修双关键词 |
| 6 | 看看这套系统业务逻辑上有没有漏洞 | 闭环正确性意图 |
| 7 | 全面测试一下这个项目 | 语境指向发现问题而非执行既有测试 |
| 8 | 测一下禁用账号后旧 token 还能用吗 | 单点质疑，属对抗清单内——应触发并把范围收窄到单探针 |

## 不应触发（反例）

| # | 用户说 | 为什么不该 |
|---|---|---|
| 1 | 什么是端到端测试？ | 概念解释，非行动指令 |
| 2 | 帮我给 parseLrc 这个函数写单元测试 | 写代码任务，不是托管式全面排查 |
| 3 | review 一下这个 PR 的 diff | 静态代码评审，另属他技 |
| 4 | 这个报错怎么修？ | 已知问题 debug，无找茬意图 |
| 5 | 给我讲讲你们测试报告的格式 | 询问产物样式，不要求执行 |
| 6 | 帮我把 npm test 跑起来 | 执行既定命令的环境操作 |
| 7 | 设计一张登录功能的测试用例表 | 要求产出文档，非独立找人找错 |
| 8 | 这段代码优雅吗 | 主观代码风格闲谈 |

## 通过标准

- 正例 8/8 触发（其中 #8 允许先向用户确认是否仅打单点再全套自举）；
- 反例 0/8 触发全套流程——纯问答类允许模型口头回答并顺带提及本技能存在，但不允许自行拉环境开测；
- 连续两次措辞改动后有任一例外，即视为 description 回归，应回滚措辞而不是放宽判定。

## 局限声明

本集为人工粘贴验证用例集，暂无自动化 harness（不同宿主工具的技能调用接口各异）；自动化方案待宿主侧有统一评测通道后再补。
