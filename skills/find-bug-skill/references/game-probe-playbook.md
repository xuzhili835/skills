# 实时渲染应用探针 playbook（游戏 / canvas / 3D）

**加载时机**：被测对象含实时渲染（canvas/WebGL/three.js 等），由正文步骤 1 可达性审计或步骤 4⑦ 指入。本文件是工具与模板，不是条款——发现新失效模式仍走正文的条款准入三道闸，本文件只收纳"怎么测"，不新增"测什么"的必查项。

## 0. 可达性审计（先于一切，产出三层归类的依据）

页面打开后（有头/无头皆可），在页面上下文摸底：

- **全局对象**：`window` 上挂的 `game/world/player/camera/scene/engine/app` 等；three.js 特征：`renderer.domElement`、`scene.traverse` 可用。
- **判定**：能读实体/相机/动画器状态→**状态层探针可用**；能注入 rAF 泵帧→动效可控；console 可订阅→**日志层可用**；页面可截图→**渲染层可用**。
- **三层全不可达**：如实写进覆盖声明，本轮只做截图走查（⑦ 的视觉纪律仍然有效），不许哑跳。
- **常见坑**：游戏跑在 iframe/worker 里（先切进对的 frame 再取状态）；无头下 canvas 尺寸为 0（显式给视口）；动画基于 rAF，无头不泵帧就永远停在第一帧。

## 1. 三层归类（业务三层验证的"皮"，纪律不换）

| 正文里的层 | 实时渲染应用的实例 | 断言手段 |
|---|---|---|
| API 层 | 游戏状态层：实体/相机/动画器/弹道/输入 | 页面上下文逐帧读值，数值断言 |
| DB 层 | 落盘与派生：存档/计分/配表（如有） | 直读 localStorage / IndexedDB / 文件对账 |
| UI 层 | 渲染输出层＋HUD | 截图问询（⑦ 四纪律）＋ console 日志 |

## 2. 默认节拍单（画像后按项目增删，专属节拍记项目校准单）

| 节拍 | 注入输入 | 截图问题示例 | 探针断言示例 |
|---|---|---|---|
| 出生 | — | 姿势是 T-pose 吗？贴图裂吗？ | 出生点=配置点；当前 clip=idle |
| 移动 | 前/后/左/右各 1s | 脚滑地吗？朝向对吗？ | 位移≈速度×时间；朝向=移动方向 |
| 跳跃 | 空格 | 起跳/落地姿态自然吗？ | y(t) 呈抛物线；落地回 idle |
| 交互 | E/点击 | 手与物件贴合吗？ | 交互距离阈值内才触发 |
| 攻击 | 左键×N | 枪挂哪只手？枪口朝前吗？ | 命中目标=准心所指；弹道点序列可回放比对 |
| 受击 | 让其被击中 | 受击反馈有吗？ | 血量减少；受击动画真实触发 |
| 死亡/重开 | 打到死 | 倒地/重生正常吗？ | 状态机 death→respawn；计分复位 |
| UI 开关 | Tab/Esc | HUD 遮挡场景吗？ | 菜单开着时游戏输入应被吞 |

## 3. 探针骨架（复制即用，字段按项目改）

### 3.1 状态快照（rAF 泵帧版，无头必需）

```js
// 无头环境 rAF 不自动跑,手动泵 n 帧;有游戏内 render/step 就直接调
async function pump(n, game) {
  for (let i = 0; i < n; i++) {
    if (game?.render) game.render();
    await new Promise(r => requestAnimationFrame(r));
  }
}
// 每拍采一行:时间/相机/目标实体/动画状态——断言用数值,别用截图替代数值
const rows = [];
for (let i = 0; i < 60; i++) { await pump(1, game); rows.push({
  t: performance.now(),
  cam: game.camera.position.toArray(),
  pos: game.player.position.toArray(),
  clip: game.player.animation?.currentClip ?? null,
}); }
```

### 3.2 穿模几何探针（视觉报穿模后的定罪手段）

思路：可疑部位取骨骼世界位置做球/胶囊，对相邻网格求交；**误报治理**：先在正常姿势录一段基线相交深度，超出基线 p95 才算异常——持枪贴胸这类合法贴合靠容差排除。

```js
// three.js + three-mesh-bvh 示意
const p = handBone.getWorldPosition(new THREE.Vector3());
const hit = bodyMesh.geometry.boundsTree.intersectsSphere(new THREE.Sphere(p, r));
```

### 3.3 console 日志订阅（三大高信号源）

开页前挂 `page.on('console')` 与 `page.on('pageerror')`。高信号：WebGL 警告、资源 404/加载失败、坐标含 **NaN**（位置 NaN 直接 P2 起步——状态已坏，后续一切表现不可信）。

## 4. 截图问询格式（每张必填，随报告归档）

```
[截图#n | 节拍:攻击]
问题:枪应挂在右手骨骼、枪口朝前——是吗?
参照:ref/hold.png(或"用户口径:……";无参照→写"无,按声明假设:……")
判定:符合 / 存疑 / 不符 + 一句像素依据
处置:不符→换角度重拍(两遍确认)→探针定罪→P?-n;存疑→观察项
```

## 5. 参照系与边界

- **公开目录**：走查参照用 Pinelle 等《Heuristic Evaluation of Video Games》的游戏启发式（对应正文 Nielsen 的位置），引用思路不另造词。
- **规则来源优先级**：用户参照（参数/截图/口径）＞ 仓库文档 ＞ 显式声明的假设；写不出"规则：应怎样"的发现只能进观察项。
- **不可自动化，写覆盖声明**：手感（灵敏度/后坐力口味）、步态与动效质量、"像不像"原作的终审。
- **成本纪律**：截图采样不连拍，单轮封顶（建议 ≤40 张），全部落盘随报告归档。

## 6. 校准单接线

收尾时把本轮新确认的视觉/探针发现按正文校准单格式（症状→最小复现探针→兜住的规则）追加进**被测项目**的校准单；游戏专属节拍、参照图路径、可达性结论一并记入，随仓库走——本 playbook 保持通用。
