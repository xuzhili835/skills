# iterate-model — 模型长程迭代方法论

这个 skill 编码的是**过程纪律**,不是技术处方。它不告诉你"该试 flipud 还是 WBF"——那取决于当前领域和数据;它告诉你:开跑前先锁定什么、按什么顺序试、什么时候停、怎么诚实记账、怎么收尾交接。领域知识永远从当前仓库的文档里来,不从本 skill 里来。

写进本 skill 的反面教训(真实发生过):一次检测迭代里,"连续 2 组无提升就停"的纪律被套在了单组仅 6.5 分钟的便宜实验上,大量高价值实验没跑就收工,用户醒来看到 0.088 而不是本可拿到的 0.541。**停止规则必须与单次实验成本匹配**——这是本 skill 存在的第一理由。

**长程靠什么成立**:对话会被压缩、会话会断,唯一可靠的载体是磁盘上的状态——每实验 JSON、轴队列、文档。本 skill 所有落盘要求为同一目标服务:**任何时候关掉会话重开,都能从盘上接着跑**。文档不是收尾的装饰,是长程迭代的传动轴。

## 第 0 步:入职——先查盘,再读仓库,再想动作

- **查盘优先**:仓库的 artifacts/、runs/、docs/ 下若已有实验 JSON、队列、迭代文档,先从盘上重建状态(读队列文件、最近几组 JSON、迭代文档最后一轮),直接续跑上一轮,**不问用户"从哪开始"——盘上有答案就别问人**。两种中断分开处理:实验被杀在半路的,有框架断点(last.pt/checkpoint)就 resume 续跑,没有就整组重跑(种子固定可复现,"没落 JSON 等于没跑");项目级暂停后恢复的,先重检协议里的预算与环境项(电源/磁盘/显存/暂停原因是否仍成立),再续。注意最常见的打断是**用户直接点停止按钮或关掉会话——无收尾、无告别**,一切"被通知后再收尾"的设计都不可依赖:恢复时最后一组一律按半成品处理(产物目录在、JSON 不在 = 没跑完);续跑前先确认旧进程真死了(显存占用/端口/后台任务,防双开),便宜实验清掉半成品目录整组重跑,昂贵实验有断点权重才 resume。
- 必读文档(缺的现建,开篇声明"待补"):迭代记录 / 交接总览 / README / 需求文档——前人试过什么、什么失败了、坑在哪。
- 从中提取六样东西:
  1. 主指标与口径(谁算的、什么工具、和谁比)
  2. 验收集在哪、怎么来的
  3. **泄漏单位**(见下)
  4. 单次实验成本(分钟、显存、磁盘)
  5. 领域先验(对称性、不变性、工艺/光照惯例)
  6. 已知失败方案清单
- 顺带完成**文档角色认领**(见"文档体系"一节):项目已有的文档按角色认领续写,不造新的。

**泄漏单位**是"同源样本不能跨训练/验收两边"的分组粒度,必须推出来或问出来:同一块板的多张图、同一硅片号的多个切片、同一工件的多角度照片、同一病人的多次检查。按文件名去重不够——同源样本经常不同名。例:光伏文件名 `{目录}_{硅片号}_{切片号}`,泄漏单位取倒数第二段;同硅片跨目录出现时,整片只能待在一边。

## 第 1 步:协议先行——写下来,再开跑

长跑开始前,把协议写进**本轮轮次总结的草稿**(位置见"文档体系"),作为预先承诺,防事后合理化。模板在 `references/templates.md`:

1. **冻结验收尺**:按泄漏单位切出、永不参训的样本集,成绩只在这上面报。比例参考 15-25%,分层对齐类别/来源分布。内部验证集另设,做过程参考;两榜打架时冻结尺仲裁,但冻结尺不用于早停、不反复窥视。**每次动用冻结尺(出场)都登记:时间、目的、是否影响决策**——出场台账公示在轮次总结里,让"看了几次"变成可审计的数。
2. **泄漏审计**:切完先审计(跨两边共享泄漏单位的样本数必须为 0),再训第一个模型。审计顺手记录:每类图数/框数、框尺寸分布、解析健全性(退化框/越界/文件名对不上)。
3. **选型规则**:哪个指标、哪个集合决定冠军——先声明。报成绩必须双口径(内部 + 冻结)一起给。协议可声明第二指标(如他人排行榜口径),但它只用于对照展示,永不参与冠军判定。
4. **停止规则**:按单次成本定(见第 3 步)。
5. **预算与环境**:预计轮数与时长(裸触发且用户未说时长时,默认声明 2 小时并直接开跑);无人值守长跑前先处理挂机风险(电源计划等)并告知用户。

## 第 2 步:基础设施——把"多跑一组"压到一条命令

每组实验一条命令可复跑,产物自动落盘:
- 固定种子、固定协议的 run 脚本;实验名(M1/M2/…)即目录名
- 每组一个 JSON:超参、变更轴、内部指标、冻结尺指标、训练分钟数、时间戳、结论(champion/positive/flat/negative/failed)
- **轴队列文件**:协议里的轴清单单独成一个文件,每完成一组就打勾 + 一句结论 + 更新当前冠军。这是断点续跑的锚——队列头就是下一个动作。

为什么:边际成本决定迭代上限。每组手工汇总 10 分钟,梯子爬不了 20 级;一条命令 + 自动 JSON,才能"想到就跑"。

## 第 3 步:梯子——按期望值/成本排轴,单变量推进

**先审计后训练**:数据层的证据(来源分布、口径差、类别失衡)决定哪些动作期望值最高。小数据(千级样本以下)项目里数据动作通常 >> 模型动作,别一上来调模型。跨项目沉淀的方法级先验见 `references/lessons.md`——**是先验不是处方**,每条带失效条件,新领域先测再信、被推翻就改写。

轴的常见类别(按典型 EV/成本排序。**是类别不是处方**,具体动作由审计证据和领域先验推导):
1. 数据合并与对齐:多来源数据能否互训?口径冲突(同类不同标注松紧)先量化再合并
2. 数据修复:解析错误、退化框、口径不一致的修正
3. 类别再平衡:稀有类过采样 / 损失加权
4. 领域先验增广:把领域的不变性/对称性翻译成增广轴去测(例:晶圆上下近似对称 → flipud。不是让你抄这个,是让你为当前领域找等价物)
5. 输入分辨率
6. 模型容量(注意显存墙;OOM 即记录并换轴,不硬刚)
7. 训练参(epochs / 学习率调度)
8. 编队:融合 / TTA / 权重平均——**前提**是各权重同数据同口径训出,否则大概率负收益(存在三种编队在口径不一致数据上全部翻车的实例)
9. 算法层:loss / 架构 / 半监督 / 蒸馏——升级判据:工程层轴用尽且连续收益 <1 个点才上

**单变量纪律**:一次只改一个轴,与上一组对照;同时改两个,涨了也不知道谢谁。

**停止规则(本 skill 的核心)**:
- 便宜实验(分钟级):只要还有未测的高期望值轴,**继续跑**。连续无提升不是停止理由,是换轴信号。
- 昂贵实验(小时级):预先声明预算,连败计数可作辅助停止线。
- 禁止把贵实验的纪律套在便宜实验上(会偷懒收工),也禁止把便宜实验的无限续跑套在贵实验上(会烧穿预算)。
- 结束条件:轴清单清空,或剩余轴期望值低于时间成本。
- 预算执行:剩余时间已不够下一组的预计成本,就不开新组,直接收尾写总结;预算到点时正在跑的组——便宜实验让它跑完落 JSON(多等几分钟),昂贵实验到点即停、按第 0 步半成品规则处理。

## 长程循环与无人值守——迭代怎么真的转起来

**循环体**(每组实验都是完整一圈):
选队列头的轴 → 跑 → 落 JSON → **当场判定**(champion/positive/flat/negative/failed)→ 更新队列与当前冠军 → 立即下一组。判定和选下一轴不攒批,结果出来当下做;攒批的判定会在会话断裂时丢失。

**停止需要引用规则**:想收工时先自问"轴清单清空了吗?预算到了吗?"——都没到就继续。"连续几组没提升"只在停止规则明确声明了它时才算数,否则它只是换轴信号。

**托管协同**:用户说"我要睡了 / 交给你了 / 通宵跑",或**裸触发本 skill 且未另说时长**时,按 autopilot 姿态执行——不逐组请示,自主选轴跑完队列;裸触发且用户未说时长,默认声明 2 小时预算写进协议后直接开跑,消息里带时长则以用户为准。**blocker 不是刹车**:遇到做不了/不该做的事,标记 blocked、跳过、继续跑其余能做的轴;停止时刻只由停止规则决定(预算尽/队列清空),不由撞墙决定。红线是"不做"的条件,不是"停下问"的条件——发现泄漏就自救:停用受污染产物、重切、重审计、重跑受影响组。不可逆动作(push、批量删除、动共享配置)不问也不做,记入 deferred。验收口径缺失时先做不依赖它的部分(审计/基建/临时内部基线,明确标注"临时口径"),不烧预算赌没对齐的指标;唯一允许提前收尾的情形是剩余全部工作都依赖同一个缺失决策——此时收尾本身就是预算的正确用法,不是"停下问人"。收尾报告固定含"绕过的墙"一节:blocked/deferred/待用户确认逐条列出,回来的人先读它。收工条件同样是停止规则满足 + summary 写完。

**中断恢复**:会话断了/上下文满了/被用户停止按钮直接掐断(无收尾机会)——不管哪种,重新触发本 skill 时按第 0 步查盘续跑。所以每组实验落盘前不算结束——"跑完但没落 JSON"等于没跑;开跑一组前先在队列文件里把它标成"进行中",恢复时队列头的"进行中"就是半成品组(标记约定见 templates.md 模板 3)。

## 第 4 步:诚实记账——负结果是一等公民

- 每组必落 JSON(第 2 步);失败/持平/变差照记,收尾时负结果单独列表——"试过且没用"与"没试过"是两种完全不同的知识
- 数据层断言(如"两批口径不同")必须有证据:统计对拍 + 抽样可视化拼图,别只报数字
- 口径差异要声明:不同评测工具有系统性偏移,只在同一管线内做 A/B,不跨管线比大小
- 选型看内部验证,报成绩看冻结尺;冻结尺被"看"的次数越少,数字越可信
- **重放断言**:引用或对比历史数字前,先在当前管线重放一个已知结果,逐位对上才采信新结果——口径漂移(数据/代码悄悄变了)靠这个拦住

## 文档体系——四角色,认领优先,一处事实一处写

| 角色 | 粒度 | 习惯位置 | 写什么 | 写给谁 |
|---|---|---|---|---|
| 状态(机器层) | 每实验/实时 | artifacts/(JSON、队列、证据图) | 高频覆写,精确不求美 | 下一个动作 |
| 轮次总结 | 每轮一份 | artifacts/<轮>/summary.md | 协议、对照表、归因、负结果、下轮入口 | 下一个会话、reviewer |
| 滚动日志 | 项目一份,每轮追加一节 | docs/迭代记录-<项目>.md | 轮级摘要 ≤10 行 + 指向轮次总结的路径 | 半年后的自己 |
| 总览(当前态) | 项目一份,只留现状 | docs/交接总览.md | 当前协议、当前冠军、数据资产 | 接手的人 |

- **认领优先**:入职时按角色认领项目已有文档(PCB 的 test_eval 演进记录、光伏的 迭代记录-wafer.md 都是滚动日志角色),沿用它的名字和格式续写;只有角色缺失才按模板新建。**绝不造平行文档**——同一事实的第二份副本必然漂移,漂移的文档比没有更危险。
- **事实源方向两种皆可**:轮次总结为事实源、日志做摘要指针;或追加式台账为事实源、叙事文档指向台账(PCB 式:《模型迭代记录》是唯一事实源,《复盘文档》指向它)。认领已有文档时跟随它的既有方向,不自创第三种。
- **去重规则**:一处事实一处写,别处给路径。对照表只在事实源;日志条目只做摘要+指针;总览只写"现在",历史在日志里;协议变更才动总览。
- 轮次总结草稿在开跑前就建(装协议),收尾时补全成正式版——文档跟着实验长出来,不是事后补写。

## 第 5 步:收尾——给下一轮留入口

- 轮次总结定稿:协议、数据事实、全实验对照表(双口径)、涨分归因、负结果清单、产物口径说明、下轮入口建议
- 叙事复盘件(PCB《复盘文档》式的增值层,轮末选做但交付/答辩前必做):**问题线复盘**(按"当时卡在什么→试了什么→结论、后来被谁反复使用"重讲一遍,不复述时间线)、**丢掉又捡起/用过又丢掉**清单(被否决但值得换身份重试的,写明重启前提)、**考卷审计**(内部验证是否被在位模型污染、验收集噪声估计)、**拆零件对照**(拆掉系统任一组件会怎样,有实测才写)、**白话层**(给非专业读者的名词解释与完整算例)
- 滚动日志追加本轮一节(摘要+指针);总览同步协议级变更
- **经验回填**:本轮学到的、换领域仍成立的方法级规律,回填 `references/lessons.md`(带失效条件);领域事实回填本仓库文档,两者不混
- 权重清理:留冠军 + 有明确用途的少数,删中间产物并报告磁盘变化
- 环境报告:本轮在 C 盘/缓存/临时目录的间接占用(是什么、在哪、多大)、依赖与显存变更
- 提醒用户恢复为长跑改过的系统设置(电源计划等)

## 红线

- 冻结验收尺永不参训、不参与早停;发现泄漏立即停、重切、重跑审计
- 选型与验收分离;不为好看的数字换口径或换集合
- 长跑占用的资源(磁盘/缓存/下载)如实报告,遵循用户全局的 C 盘规则
- 不 push、不提交含隐私的产物,除非用户明确要求
- 停下时必须已写完轮次总结——没写总结的停止等于白跑
- 不为"看起来有产出"另造平行文档

## 评测适配(不同任务形态,循环不变)

- 检测/分割:mAP 系 + 每类 AP,按泄漏单位分组
- 分类:准确率/F1 + 混淆矩阵,按来源分组
- 回归/几何算子(如 CAD 尺寸、剖切规划):固定验收题集 + 容差通过率,当回归测试跑
- 没有明确验收集时:先和用户对齐"用什么数字判好坏",再进第 1 步
