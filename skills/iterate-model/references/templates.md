# iterate-model 配套模板

六份模板:协议预承诺、每组实验 JSON、轴队列状态文件、轮次 summary、滚动日志条目、总览协议块。直接抄改,不要凭记忆重写结构。这些是**空白表格**;带真实内容的范本看各仓库的历史文档(如 PCB 的《模型迭代记录》《复盘文档》)。

## 1. 迭代协议(开跑前填,贴进本轮 summary 草稿)

```markdown
## 第 N 轮协议(日期:YYYY-MM-DD)
- 主指标:<如 冻结尺 mAP50-95,评测工具 XX>
- 内部参考:<内部验证集 + 指标,过程用>
- 冻结验收尺:<来源/切法/泄漏单位/规模,如 120 图 91 片>,绝不参训
- 泄漏审计:<已跑,跨两边共享泄漏单位数=0 / 待跑>
- 选型规则:<内部验证 X 最高者为候选,冻结尺终评定冠军;平局时取…>
- 停止规则:<单组成本 X 分钟 → 轴清单清空即停 / 预算 Y 小时 + 连败 Z 组辅助>
- 预算与环境:<预计轮数/时长,裸触发未说时长默认 2 小时;电源计划等挂机风险处理>
- 绕过的墙(blocked/deferred):<开跑后逐条追加:什么事、为什么绕过、需要谁拍板>
```

轴清单单独存成队列文件(模板 3),协议里只写"队列见 <路径>"。

## 2. 每组实验 JSON 最小字段

```json
{
  "name": "M4",
  "changed_axis": "flipud 0.5(对照 M3)",
  "data": "D:/…/data.yaml",
  "epochs": 100,
  "seed": 20260901,
  "train_minutes": 22.3,
  "internal": { "mAP50": 0.0, "mAP50-95": 0.0, "per_class": {} },
  "freeze": { "mAP50": 0.0, "mAP50-95": 0.0, "per_class": {} },
  "verdict": "champion | positive | flat | negative | failed",
  "finished_at": "YYYY-MM-DD HH:MM:SS"
}
```

要点:`changed_axis` 必填且只填一个(单变量纪律);`freeze` 只在候选定型时评,不每组早停;`failed`(跑崩/OOM)也要落盘,注明原因。

## 3. 轴队列状态文件(断点续跑的锚,开跑标"进行中",完成即更新)

```markdown
# 第 N 轮轴队列
- [x] A1 合并双批数据 → M1(flat)M2(+38pt,champion)
- [x] A4 领域先验增广 flipud → M4(+5.6pt,champion)
- [-] A6 容量升级(进行中,开跑于 HH:MM)
- [ ] A8 编队(前提:同口径权重)
当前冠军:M4(权重路径,freeze 成绩)
最近更新:YYYY-MM-DD HH:MM
```

要点:状态三值——`[x]` 完成(带一句结论)、`[-]` 进行中(**开跑前先标**,含开始时间)、`[ ]` 未跑。`[-]` 专为无收尾打断设计(用户点停止按钮/断电/会话被杀):恢复时队列里残留的 `[-]` 就是半成品组,按"没落 JSON = 没跑"处理——先确认旧进程已死(显存/后台任务,防双开),便宜实验清半成品目录整组重跑,昂贵实验有断点权重才 resume;处理完把 `[-]` 改判为 `[x]`(重跑后)或在结论里注明"被掐断,未完成"。

## 4. 轮次 summary.md(开跑前建草稿装协议,收尾定稿)

```markdown
# 第 N 轮迭代总结(日期)
1. 协议(本轮变更及理由)
2. 版本速览:全部版本/实验 × 固定列对照表(同一测法;加粗 = 该列最优;★ = 当前交付)
3. 数据事实(审计证据 + 证据图路径)
4. 问题线复盘:按"当时卡在什么 → 试了什么 → 结论、后来被谁反复使用"重讲,不复述时间线
5. 涨分归因表:改动 → 收益 → 要点(零训练收益单独标注)
6. 负结果清单 + 丢掉又捡起/用过又丢掉(被否决但值得换身份重试的,写明重启前提)
7. 考卷审计:内部验证是否被污染、验收集噪声估计、冻结尺出场台账(逐次登记:时间/目的/是否影响决策)
8. 产物口径:权重/JSON/证据图各在哪,口径注意点(谁和谁能比)
9. 磁盘与环境:保留/清理了什么,各多大;C 盘间接占用
10. 下轮入口:建议优先试的三件事,按 EV/成本排序
```

交付/答辩前另做叙事复盘件(PCB《复盘文档》式):任务与指标的白话定义、系统走一遍(含完整算例)、拆零件对照、编年史(每版以"学到:"收尾)、项目结构说明书。事实与数字仍以事实源文档为准,复盘只指向它。

## 5. 滚动日志追加条目(docs/迭代记录-<项目>.md,每轮一节)

```markdown
## 第 N 轮(日期~日期)
- 变更:<协议/数据层面的一两句话>
- 结果:内部 X→Y,冻结 X→Y;冠军 <实验名>
- 负结果:<一句,重要的列名字>
- 详见:<轮次总结路径>
```

事实源方向:若项目沿用的是 PCB 式**追加台账**(逐版全量细节、只增不改写),则台账是事实源,上面的条目模板不适用——直接按台账既有格式续写,叙事文档指向台账。认领时看项目已有方向,不自创第三种。

## 6. 总览协议块(docs/交接总览.md,只保留当前态)

```markdown
## 当前迭代协议(更新于 YYYY-MM-DD)
- 验收尺:<切法/泄漏单位/规模/路径>
- 选型规则:<…> 停止规则:<…>
- 当前冠军:<实验名,权重路径,双口径成绩>
- 数据资产:<训练池/内部验证/冻结尺的路径与规模>
- 历史:见 迭代记录-<项目>.md
```
