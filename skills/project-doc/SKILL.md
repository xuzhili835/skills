# project-doc — 项目工作文档

## 路径锚定（迁移与换机规则）

- 本 skill 的材料主源锚定**一个根目录**：本机 = `D:\Desktop\实训文档\`。下文出现的模板、素材、成品路径都锚定于此根（绝对路径只是"根+后缀"的展开写法）。
- **根不存在时（换机器、skill 迁移、目录搬家）**：先在常见位置找 `实训文档\README.md`（该目录自带自解释入口，见它即确认找到根）；找不到就**直接问用户要新根路径**，不按旧路径猜、不因路径失效放弃任务。换根只改本节一行，其余路径不动。
- 模板原文件只存实训文档\素材\（单一副本）；skill 只记位置与结构描述，不把模板二进制拷进 skill 目录——模板出新版时天然只有一处要改。

## 流程（顺序固定）

1. **收集素材，双通道都做**：① 用户口述；② 主动提炼——扫工作目录里最近的脚本、数据、文档、遗留产物，列出"本轮可写材料清单"请用户勾选。对话可能发生在任何目录，不假设素材在眼前。
2. **写前对齐**：先给提纲（几节、每节写什么），确认后动笔。
3. **初稿**：按分流风格写。
4. **去AI味**：初稿完成后独立过一遍 references/de-ai-rules.md，逐段对照；不边写边改。**复盘 PPT 的页标签/图注/要点也是文案，同一遍过**——图注短，最容易被当成"不算文案"跳过（2026-10-15 图注黑话"渲染层不吃/重产"漏网教训）。
5. **自检**：对照下方风格清单与 samples 对应基准。

## 工作日志（两线周报共用的素材主源）

- 日志按周一个文件，放 `D:\Desktop\实训文档\工作日志-<周区间>.md`（与周报同区间、终点周日）。每次干活收尾把当日条目追进当周日志；写任一周报**第一步先读当周日志**，日志缺的按文件时间线回填并补进日志（标"补记"）——防上下文压缩导致漏事、偏向最近。
- 条目三类标记，取材去向不同：
  - 普通条目：做了什么、产出、关键数字 → 两线周报通用；
  - **EXP 实验**：编号 EXP-XXX、改动点、动机、指标变化（数值）、结论（有效/无效/待定）→ 青软周报第二节"实验卡片清单"与素材登记表"关联实验编号"取材于此；
  - **知识采集**：日期、谁讲的、要点（1-2-3）、固化方式（录音/纪要/未固化+原因）→ 青软周报第四节取材。

## 周报日期规则

截止：每周日之前。**文档日期一律写所覆盖周次的区间，终点固定为周日**——周五下班写的也写当周周日，标题形如"2026.09.21-2026.09.27工作总结"（研究院）/"2026.09.21-2026.09.27实训周报"（青软）。补写往期则写那周的区间。
青软抬头"第＿周"的**周次锚点已定**（2026-09-28 用户确认）：**第 1 周 = 2026.09.21-2026.09.27**（首份研究院周报覆盖的那一周），其后每 7 天顺延（09.28-10.04 = 第 2 周，以此类推）。抬头写"第N周"并照写区间；往后写周报先按此换算周次。

## 研究院周报特有约定

- **结构固化、内容灵活**：五节骨架、两张表的列、标题日期格式、完成情况词表不许动（固化清单见 references/style-samples.md C 节）。内容自由填写，但新技术、踩坑、贴图等扩展内容一律融进对应项目条目或总结段——**不新增节、不改节名**。
- **样式固化**：weekly_template.js 已内置研究院模板样式——表头深青 156082 白字、数据行浅灰蓝 CCD2D8、总述行杏色 F6C6AD、表格无框线纯色块、标题宋体三号居中不加粗、节标题宋体 12pt 加粗。不为周报引入别的版式；模板原文件在 `D:\Desktop\实训文档\研究院\素材\研究院周报模板.docx`。
- docx 由 references/weekly_template.js 生成：填一份数据 JSON（形状见脚本头注释），`NODE_PATH=... node weekly_template.js 周报数据.json`；"存在的问题"为空则整节省略。成品放 `实训文档\研究院\`。
- 上期报告的"下周工作内容"表 → 本期"上周工作计划"表（补"完成情况"列）。完成情况用模板词表：已完成 / 基本完成 / 完成XX% / 进行中 / 未完成。
- **pptx 版（2026-10-03 模板到位，恢复可用）**：模板在 `D:\Desktop\实训文档\研究院\素材\周报模板.pptx`（16:9，11 页，结构已核对）——封面（主题一句话 + "XX.XX-XX.XX工作汇报" + **姓名为模板自带占位，出稿必须换成本人**）；四节式：一、上周工作计划（表列=预期任务/预期完成时间/预期达到效果/完成情况，**完成情况词表与 docx 版完全一致**：已完成/基本完成/完成XX%/进行中/未完成）；二、本周工作内容（按项目分页，(1)(2)(3)完成事项+结果或数据，另有"效果展示"页=3 图横排+图注）；三、目前存在问题（现象/已定位原因/当前状态）；四、下周计划（表列同上周计划）。机制走 presentations:pptx skill，**改模板副本、不动原模板**；出 docx 还是 pptx 按用户当次指定。pptx 生成器不预先蒸馏，第一次真出 pptx 周报再把版式参数固化进 references/。
- **朴素口径（2026-10-16 用户纠偏："这个 ppt 基本上就是从 word 截取下来的，不用目录啥的装饰"）**：模板自带的封面后四张节过渡页（只有"一、二、三、四"词条）一律删，出稿 7 页=封面+计划表+内容页+效果展示+问题+计划表，页面贴 word 内容结构，不加任何目录/导航/装饰页。
- pptx 出稿两坑（2026-10-16 首轮回写）：①模板两张计划表各预留一整行空行，出稿前删掉（visual-judge 会判 fail）；②python-pptx 删 slide 必须 `prs.part.drop_rel(rId)` + `sldIdLst.remove(sldId)` 两步——只 remove 引用会留 orphan part，保存时 zip 出重复条目，PowerPoint/WPS 有报损坏风险（修法：按文件名去重重建 zip，同名取最后一个）。

## 青软实训周报特有约定

- **交付时点（用户 2026-09-28 补充）**：每周只交《实训周报》一份；素材登记表与案例六件套是**项目收尾统一交**——平时滚动积累（登记表随手记、六件套件4实验链随实验卡片攒），不随周报提交。
- **筛选原则（2026-09-28 定）**：周报只写**业务工作**；面向自己的 meta 工作——文档整理、AI 协作过程、内部纠偏教训（如计划表误删）——只留工作日志，**不进周报**。日志记全量（私有底稿），周报做对外筛选。
- **交付物措辞（2026-09-28 定）**：凡要提交给对接人的东西（周报/方案/交付代码及其注释/说明），不出现"工程师口径"等指向对接人本人的字样——改用"业务规则：……"；口径出处只写在周报"知识资产采集"表的"谁讲的"列（那是模板要求的出处列）。
- **截图（2026-09-28 起）**：周报要界面/结果截图时 **AI 代截**，不用用户手动——启动查看器（后台跑 stp_viewer.py）→ playwright-cli 无头 `setInputFiles('#file', 零件stp)` → 等判定面板出 → 点 `.ev.click` 证据行截高亮；截"面板全景 / 高亮效果"两类即可。截图存 `青软\素材\截图\`，数据 JSON 的 `shots` 字段挂在第二节表格下（[{img, caption}]，img 相对 JSON 目录），**不新增节**。图注写清"改动前→改动后、功能变化"；旧状态已不可复现时只截当前态、对比用文字写，不摆拍。
- **结构固化**：六节（任务完成情况 / 实验卡片清单 / 产出素材登记 / 知识资产采集 / 踩坑与解决记录 / 下周计划）+ 附录实验卡片卡式。节名与表列**不增不删**（qingsoft_weekly.js 已固化）。
- **空节规则（用户 2026-09-28 定）**：无法填写的节保留节名，表内出一行"无"，**不删节、不省略**——qingsoft_weekly.js 对缺省字段自动出"无"行。
- 实验卡片当天记（进工作日志 EXP 条目），周五汇总进第二节；第三节对接 `实训文档\青软\素材登记表.xlsx`——一条一记，含类型（数据/代码/知识/过程）、脱敏状态、归档路径、关联实验编号；该表现阶段手动维护，自动追加等第一次量大再蒸馏。
- **脱敏口径（用户 2026-09-28 定）**：青软与研究院是合作关系，企业名与项目内容可如实写；账号、凭据、密钥类信息仍绝不出现。
- **样式**：表头淡蓝 D9E2F3 黑字、全表细框线 0.5pt、大标题黑体三号加粗居中、节标题黑体 13pt 加粗、正文宋体 10.5pt、附录说明楷体 9.5pt；模板原文件在 `实训文档\青软\模板\`。
- 案例六件套（任务书/数据卡/Baseline卡/实验链/规范/对比报告）：项目收尾大件，生成器**延后蒸馏**——第一次真要交再做；其中件4"实验链"= 全部实验卡片按时间线汇编（不删失败实验），取材自日志 EXP 条目。

- **类比与示意先过正确性自检**（2026-10-16 A4 教训）：拿日常物做几何/物理类比，逐句自查"这个性质上类比物与目标一致吗"——A4 纸绕长边转 90° 应"压成一条线"，写成"看到完整矩形"就是类比失真；示意 SVG 同样按真实投影关系画，不凭感觉摆。示意用的派生产物**不降精度口径**：曾用三角网格采样画剖面线被用户以"3转2 面直接投影为线"打回，改为断面精确实体边离散+求交。

- **docx 版式两坑**（渲染目检抓出，2026-10-16）：术语表/长表格跨页截断（表行加防跨页设置）；插图与图注、周边文字重叠（渲染图核对图宽与段距）。

## 里程碑复盘 PPT 路线（2026-10-14 新增）

- **何时做**：一个里程碑闭合（验收通过 / 封板 / 交付定稿）之后。**不由日历触发**——AI 在会话中发现里程碑闭合信号时主动提醒一句"要做复盘 PPT 吗"（里程碑不按时间固定来），也可随时手动召唤（"做复盘 PPT / 里程碑复盘"）。
- **产物**：`实训文档\对接文档\<项目>\<日期>_<项目>_<主题>.pptx`（日期=里程碑闭合日；这是**交工程师的成品，归研究院侧，不放 个人\**）。生成脚本留项目工作目录。
- **版式基线=极简**：16:9、无封面、无目录、无装饰页，每页 1~2 张截图并排 + 底部一行图注（风格参照 `ai应用工程师培训\B-rep3转2\3转2演示.pptx`，只参照风格不固化其内容）。**python-pptx 裸写，不走 presentations:pptx skill**（那边模板机制会把风格复杂化）。必要页可加 ≤3 行要点文本块，不超。
- **页面骨架（3~5 页）**：①成果 1~2 页——讲工程语言的结论（如"六标准视图全部产出、投影与原图对齐、图面干净"），**不堆内部指标**（实体数/断言数/墙钟无工程含义，不写）；②问题与解决 1~3 页——每页一个：现象截图 + **技术路线层**的解法，粒度="通过闭合环判别过滤剪影残环""改用国标 SHX 大字体解决中文显示"——不写"xx 代码写错"的实现细节，也不写"优化了算法"的空话。**遗留与下一步页默认不放**（2026-10-15 用户口径："不需要遗留与下一步这个点"；确有值得放的遗留事项，先问一句再加）。
- **取材三路**：①工作日志（问题→解决时间线主源，★条目优先）；②截图素材库 `实训文档\素材\截图\<项目>\日期_主题.png`（入库纪律见工作区 AGENTS.md：用户贴进对话框的截图当次入库）；③AI 自截（matplotlib 渲染 / AutoCAD COM / pymupdf，管线见 memory docx-render-wps-pipeline）。旧状态不可复现时只截当前态、对比用文字写，不摆拍。CAD 图优先 **PrintWindow 整窗真截屏**（黑底模型空间+Ribbon 的"真 CAD 截图"观感；方案见 cad-secdev-win11 skill 的 com-autocad.md 易错 10）——Plot 出图白底无界面，只作图形本体；局部放大不从整图裁（分辨率掉、构图松），单独 ZOOM 窗口截一张。
- **问题无存档截图时（2026-10-15 用户口径）**：素材常只是用户口头抛过的问题——按问题重现找图：重跑管线截当前态，或自行在图上做标注成对照图（如模拟用户标红：把问题实体描红）。**不必每个问答都截图入库（太臃肿），核心项目问题才值得留档**，普通问答用文字带过。
- **版面三坑**（visual-judge 抓出、2026-10-15 回写）：大图贴页边（图四周留 ≥0.3in）；图注孤字断行（长图注渲染预览，断行尴尬就改短句）；并排小注贴图（小注与图底边留 ≥0.3in）。渲染校验 = WPS 演示 COM（DispatchEx("KWPP.Application")）`SaveAs(…, 32)` 导 PDF → pymupdf 转 PNG → visual-judge 逐页过，全 pass 才收，挂了修复后再走一轮。
- 内容纪律同技术方案路线：非个人口吻、去 AI 味（成稿后真过 references/de-ai-rules.md，含第 5 条口语黑话与生造压缩）、没核对的标待核对；微软雅黑缺 Unicode 上标字形，nm/µm 用 e 记法。

## 技术方案/文档风格清单

- 篇幅克制：本路线的读者只有对接工程师本人、1:1 交接，原话"不要写太长，写的累，看的也累"——只保留他要做的判断所需的内容。**此条只约束对接工程师的方案/说明文档，不约束两线周报**（周报按各自模板体量写）。
- 纯黑白：无封面、无色块、无目录、无页眉、无版本标注。
- 黑体标题、宋体正文，首行缩进 2 字符（480），行距 1.3 倍（312）；表格用三线表。
- 只留方法：任务定义、数据规模、流程、选型及适配理由、特征/规则体系、原理。不写：背景出处、环境台账、验证结果、待确认、下一步、版本信息。
- 具体数字优先于概括词；溯源预答（规则来源、自命名特征）保留一句交代。
