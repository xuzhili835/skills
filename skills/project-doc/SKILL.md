## 路径锚定（迁移与换机规则）

- 本 skill 的材料主源锚定**一个根目录**：本机 = `D:\Desktop\实训文档\`。下文出现的模板、素材、成品路径都锚定于此根（绝对路径只是"根+后缀"的展开写法）。
- **根不存在时（换机器、skill 迁移、目录搬家）**：先在常见位置找 `实训文档\README.md`（该目录自带自解释入口，见它即确认找到根）；找不到就**直接问用户要新根路径**，不按旧路径猜、不因路径失效放弃任务。换根只改本节一行，其余路径不动。
- 模板原文件只存实训文档\素材\（单一副本）；skill 只记位置与结构描述，不把模板二进制拷进 skill 目录——模板出新版时天然只有一处要改。

## 流程（顺序固定）

1. **收集素材，双通道都做**：① 用户口述；② 主动提炼——扫工作目录里最近的脚本、数据、文档、遗留产物，列出"本轮可写材料清单"请用户勾选。对话可能发生在任何目录，不假设素材在眼前。
2. **写前对齐**：先给提纲（几节、每节写什么），确认后动笔。
3. **初稿**：按分流风格写。
4. **去AI味**：初稿完成后独立过一遍 references/de-ai-rules.md，逐段对照；不边写边改。**复盘 PPT 的页标签/图注/要点也是文案，同一遍过**——图注短，最容易被当成"不算文案"跳过（2026-10-15 图注黑话"渲染层不吃/重产"漏网教训）。
5. **自检**：对照下方风格清单与 samples 对应基准。

## 工作日志（两线周报共用的素材主源）

- 日志按周一个文件，放 `D:\Desktop\实训文档\工作日志-<周区间>.md`（与周报同区间、终点周日）。每次干活收尾把当日条目追进当周日志；写任一周报**第一步先读当周日志**，日志缺的按文件时间线回填并补进日志（标"补记"）——防上下文压缩导致漏事、偏向最近。
- 条目三类标记，取材去向不同：
  - 普通条目：做了什么、产出、关键数字 → 两线周报通用；
  - **EXP 实验**：编号 EXP-XXX、改动点、动机、指标变化（数值）、结论（有效/无效/待定）→ 青软周报第二节"实验卡片清单"与素材登记表"关联实验编号"取材于此；
  - **知识采集**：日期、谁讲的、要点（1-2-3）、固化方式（录音/纪要/未固化+原因）→ 青软周报第四节取材。

## 周报日期规则

截止：每周日之前。**文档日期一律写所覆盖周次的区间，终点固定为周日**——周五下班写的也写当周周日，标题形如"2026.09.21-2026.09.27工作总结"（研究院）/"2026.09.21-2026.09.27实训周报"（青软）。补写往期则写那周的区间。研究院 ppt 封面的日期行照 V2.0 模板用双横线连接（`2026.11.02——2026.11.08`）。
青软抬头"第＿周"的**周次锚点已定**（2026-09-28 用户确认）：**第 1 周 = 2026.09.21-2026.09.27**（首份研究院周报覆盖的那一周），其后每 7 天顺延（09.28-10.04 = 第 2 周，以此类推）。抬头写"第N周"并照写区间；往后写周报先按此换算周次。

## 研究院周报特有约定

- **结构固化、内容灵活（2026-11-06 换 V2.0 模板）**：五节=周总结/各项目细项页/下周计划，目录页当前节红色高亮（C00000），页面结构与样式照 style-samples.md **D 节**（蒸馏自周汇报模板 V2.0）不许动。内容自由填写，但新技术、踩坑、贴图等扩展内容一律融进对应项目条目或总结段——**不新增节、不改节名**。
- **内容边界（2026-10-30 用户纠偏："交给研究院的为什么会有文档与讲解：青软项目简述……？""任务书三 TB-03……不用写，我们内部协作口径都来了？"）**：只写研究院这条线的业务工作与交给研究院/对接方的正式交付物（技术汇报 PPT、技术方案 docx 都算）。**不进**：①青软实训侧文档（项目简述、实训周报、教学归档件）；②个人向讲解/学习材料（讲解视频、交互网页，归 `个人\`）；③内部协作与追踪口径（任务书分周节点的"第 N 周未交付"、仓库里有没有产物、外来快照转存约定、共享树目录分工、多 AI 窗口分工）。计划表照模板记账：上期列过的条目保留并给完成情况，其余位置不再复述。
- **交付自包含（2026-11-02 项目经理对周报与汇报 PPT 的批评泛化）**：①**计划表只写本人任务**，同事/他人负责的条目不进（外部依赖写成表下小注，不占任务行）；②**给读者的交付物要自包含**——专业缩写首次出现给一句白话解释（如 A-A/B-B＝客户图剖切符号的字母编号，各对应一张剖视图），指标必须写算法与分母口径（如 剖视匹配率＝客户图轮廓点中距我方轮廓 ≤0.5mm 的占比，分母＝客户图点数），**结论/摘要行里的百分比数字必须带对比对象**（2026-11-02 用户手改示范："结论先行（**与客户剖视图对比**A-A 100.0%…）"——裸写"A-A 100.0%"读的人不知道跟谁比，正是项目经理批评的表达不清），效果类成果必须配叠合对比图（红=客户图、绿=我方）；**制图术语用国标名，公司惯用词不当标准词**（2026-11-02 项目经理纠偏"制图界不是叫细节图的，他只是一个行业惯用词"：细节图→**局部放大图**，GB/T 4458.1，DETAIL＋比例标注；对项目经理/正式文档首选标准名，与工程师公司内部交流可照用惯用词）；③**"存在的问题"写根因导向**：机制层原因＋已知证据＋正在怎么定位＋解法方向，不能只写现象或"待诊断"；④**未发给该读者的文档产出不写进周报**（用户 2026-11-02："多一事不如少一事"——写了会被问"为什么没发我"，提请发送的事走聊天）；**补例外（同日用户纠偏）：更新"已提交过"的周报时已交内容只增不删**——被批评的条目就地改写补强（补口径、补说明），不整条删，删除动作本身会被看出动机；但**内部口径条目（如任务书节点）从计划表（含上周计划表）删掉属优化**，直接删；⑤**承诺节点变动两处同步**（如 V/W 提前到 11.03）：周报计划表与排期表一起改；**排期表与周报计划表逐行一致（含行数，不把一条任务拆成两行）**，日期只取已向对方承诺过的，不为凑排期感虚构中间节点。**排期表 xlsx（预期任务/预期完成时间/预期达到效果三列）是应点名的临时产物**（2026-11-02 项目经理批评"没考虑排期"才出的一份），不是每周常规交付、不固化进模板。⑥**"客户缺什么"只写客户图/客户需求实有的东西**，我方工具能力缺口单独归"工具储备/待接入"类，不与客户待办混写（2026-11-02 案例："复合剖"是我方 10-20 储备项，写进周报"客户剖视还缺…"后被项目经理当客户待办催期，实际客户图 FSCC 无弧线剖切；V/W 斜剖才是客户图实有的真待办）。
- **对外口径两不写（2026-11-06 用户定）**：①**"需协助/待对方报数"类技术问询不进周报**（"多一事不如少一事"——写了会被追问进展与责任；这类事走日常对接/聊天），只有需要项目经理出面协调跨组资源、不写会在项目层失真的必要情况才写；②**不点名交付物/产出物文件**（"交付了 XX 页效果汇报 PPT""外包算法问题反馈已成稿"都不写）——周报写业务工作与技术进展本身，效果用数字与图说话；发给工程师/外包方的材料一旦点名，项目经理会转头索要。模板强约束要求列交付物时才按需列。
- **样式固化（2026-11-06 起=V2.0）**：模板原文件 `D:\Desktop\实训文档\研究院\素材\周汇报模板V2.0.pptx`；样式与页面结构照 style-samples.md D 节（微软雅黑 16pt 粗 002060 正文、汉仪旗黑-55简 24pt 目录词条、目录当前节 C00000 红标、花括号/项目标签是结构不删）。不为周报引入别的版式；旧 docx 模板与旧 pptx 模板归档在同级 `归档_旧模板_2026-11-06\`，weekly_template.js 退役（文件留 references 不删，仅供回滚）。
- **产出顺序（2026-11-06 用户定）**：先按 V2.0 模板出 ppt（机制走 presentations:pptx skill 模板继承流程，改模板副本不动原模板），**word 由 ppt 产出**（ppt 定稿后从其内容提炼生成 docx，ppt 是唯一主源）；旧流程（word 为主源、ppt 从 word 复制）作废。成品放 `实训文档\研究院\`。
- 闭环（V2.0 无表格式）：上期"下周计划"页的条目 → 本期周总结逐条给完成情况；完成态写法照模板举例（"（已完成）"或补预计完成时间点），效果必须带数字口径（模板示例："直通率约为100%（100/100张图）"，测试量少要注明）；**"完全没做"的条目不写**（模板内嵌规范）。
- **计划条目必须有真实出处（2026-10-18 用户纠偏："2D 转 3D 备战调研固化/技术路线调研结论成文可用于立项评审"是自己编的）**：下周计划页、周总结里的每一条只能写当周工作日志里真实在办或卡点的事，不得虚构任务名、时间与交付物——"可用于立项评审"这类无中生有的效果描述是重灾区；生成前逐条对回日志，出处不明的宁缺毋滥、直接不写。
- **pptx 机制**：模板继承流程走 presentations:pptx skill（**改模板副本、不动原模板**；删页 drop_rel 两步防 orphan part；填文本用首 run 替换保格式，长度不超原占位 1.1 倍）；封面姓名为模板自带占位，出稿必须换成本人。版式与内嵌规范（周总结三要素、细项页/下周计划页写法）蒸馏在 style-samples.md D 节，不在此重复维护。
- **模板原样继承（2026-11-06 定，替代旧"朴素口径"三删）**：V2.0 的目录页/项目标签/花括号/配图框是**结构**不是装饰——不删、不改版式，要改的只是占位文本；字体随模板（汉仪旗黑-55简缺字体由查看端替换，不换字体名）。旧模板"删过渡页/去色块/删花括号"的三删规则随旧模板归档，不适用 V2.0。
- **去 AI 味扫描必须覆盖 pptx 全部文本，含表格 cell**（标题/图注/要点/封面主题同过词表；2026-10-16 两次漏网：只扫 docx 漏了 pptx 文本框，扫了文本框漏了表格 cell——总述行"定版/链路"藏在 cell 里）；"定版"→"定稿"、"链路"→删或具体动作、"环境对齐"→"环境一致"（几何"投影与原图对齐"是正常动词保留）。**每轮纠偏后对全部成品重跑整套词表**（含历史纠偏词），不是只扫当轮新词。
- **word 由 ppt 产出（2026-11-06 定，替代旧"ppt 从 word 复制"的同源对齐）**：ppt 定稿是唯一主源，word 从 ppt 内容提炼生成，**术语与关键措辞逐词一致，不得另起说法**——旧"两条管线措辞漂移"（ppt 已"查清"docx 还是"闭环"）从源头消除。"闭环"区分身份：管理黑话（"问题形成闭环"→"问题查清"）改，几何术语（"剪影闭合环过滤""闭环锯齿伪影"）留；"踩坑"是青软模板固化节名，不改。
- pptx 出稿两坑（2026-10-16 首轮回写）：①模板两张计划表各预留一整行空行，出稿前删掉（visual-judge 会判 fail）；②python-pptx 删 slide 必须 `prs.part.drop_rel(rId)` + `sldIdLst.remove(sldId)` 两步——只 remove 引用会留 orphan part，保存时 zip 出重复条目，PowerPoint/WPS 有报损坏风险（修法：按文件名去重重建 zip，同名取最后一个）。

## 青软实训周报特有约定

- **交付时点（用户 2026-09-28 补充）**：每周只交《实训周报》一份；素材登记表与案例六件套是**项目收尾统一交**——平时滚动积累（登记表随手记、六件套件4实验链随实验卡片攒），不随周报提交。

- **docx 版式两坑**（渲染目检抓出，2026-10-16）：术语表/长表格跨页截断（表行加防跨页设置）；插图与图注、周边文字重叠（渲染图核对图宽与段距）。
