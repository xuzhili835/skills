# 风格 ground truth（蒸馏自真实文档定稿）

> 本文件即唯一依据：以下基准蒸馏自 2026-09-23 前后的真实定稿文档，原件已由用户清理。**不要寻找或读取任何源路径**，这里蒸馏出的文字就是标准。

## A. 技术方案/文档 —— 用户手改定稿即标准

（2026-09-23 用户在 AI 初稿上**纯删除**改定，自评"这个才叫精简"）

- 体裁定性：方法说明，不是汇报。用户删掉的全是对话残渣和汇报腔。
- 用户删掉的，以后不要再写：封面/色块/目录/页眉/版本标注与作者行版本号；项目背景与任务出处段；环境依赖台账；"验证结果""待确认问题""下一步计划"整节；过长论证（压成一两句）。
- 保留的骨架（2 页内）：标题 + 一行元信息（姓名 日期）→ 一、任务与数据（2 段）→ 二、方法（流程一段 / 选型一段 / 特征体系一段 / 判别规则 + 三线表 / 树原理一段）。
- 溯源预答保留：主动一句写清规则来源（全特征训练的决策树）与特征名为自命名（非行业标准）——读者是行家，会想知道这两点。
- 版式：黑白；黑体标题 / 宋体正文；首行缩进 480；行距 312；三线表（上下粗、表头下细、无竖线）；表题加粗居中。构建器直接用 references/docx_kit.js（参数即该验收版的参数）。

## B. 调研报告 —— 同事气质参照，不复刻格式

- Heading1 题目 / Heading2 "1." 章 / Heading3 "2.1" 节；宋体正文；适度加粗关键结论与数字；有图有表；段落长短不一、直陈。
- 每个人有自己的风格，格式细节不必复刻；学的是气质：直陈、有图有数、不绕。

## C. 周报 —— 结构固化、内容灵活

结构已固化为 references/weekly_template.js（填数据 JSON 直接出稿），本节只写边界与内容规则。

**固化（脚本、节名、表列不许动）**

- 五节骨架，顺序固定：上周工作计划 / 本周工作内容 / 存在的问题 / 本周工作总结 / 下周工作内容。
- 计划表四列：预期任务 | 预期完成时间 | 预期达到效果 | 完成情况；表尾"工作情况总述"合并行。下周表三列（无完成情况列）。
- 标题：`YYYY.MM.DD-YYYY.MM.DD工作总结`，区间终点 = 周日（周五晚写也写当周周日；补写往期写那周区间）。
- 完成情况词表：已完成 / 基本完成 / 完成XX% / 进行中 / 未完成，不用其他表述。
- 闭环：上期报告的"下周工作内容"表 → 本期"上周工作计划"表（补"完成情况"列）。
- "存在的问题"无内容时整节省略（模板"无则删除本行"的节级推广）。

**灵活（自由填写，但不另起炉灶）**

- 项目数、每项目条目数、每格文字量自由。
- 新学的技术/工具/踩坑：写进它所服务的那个项目的条目里（"用X做了Y，结果Z"），或融进本周工作总结段；**不新增节、不改节名**。
- 贴图放对应条目下（脚本条目支持 img 字段），不建图片附页。
- "预期达到效果"写成可验收的描述（"支持XX输出"而非"优化XX"）。
