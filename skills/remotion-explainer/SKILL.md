# 讲解视频 / 交互教材制作

目标：让**第一次看的人**看懂一个机制或流程，而不是把文档搬上屏幕。视频适合线性过程；交互 HTML 适合需要回看、跳步、改字的资料。两者可并存，成品同归。

## 一、先选载体

| 场景 | 选 |
|---|---|
| 有先后顺序的流程、对外播放、答辩/汇报自动播放 | 视频（Remotion） |
| 需要反复查阅、跳步、标注、改字迭代 | 单文件 HTML（零依赖，双击即开） |
| 两者都要 | 共用一套 SVG 视觉与时序状态，视频渲染 mp4，网页做交互 |

视频的代价：渲染几分钟、改一个字也要重渲；交互网页的代价：要人操作。**流程演示选视频，工具说明书选网页。**

## 二、内容设计（硬规则，违反即打回）

这些是 2026-10-21 两轮打回后定下的，不是建议：

1. **术语先铺垫，再用；每个术语在画面上必须有对应物。**
   - 反例：开场直接说"候选点划线/中心线"，画面上的剖切线却画成实线——观众找不到"点划线"是什么，后面全悬空。
   - 正例：先给放大的点划线样式 + 名称 + 一句定义，再进入算法。
2. **每一步筛选/判断必须有自洽的例子，淘汰理由要安在真实原因上。**
   - 反例：把"长度不足 18mm"标在一条很长的中心线上（它连出来明明很长，自相矛盾）。
   - 正例：短段 → 长度不足；长中心线/断裂线 → 没有字母标签。每个理由都对得上画面里那个对象。
3. **数字必须带出处，示例数字必须标"示意"。**
   - 实测值写"实测于 N 张图"；源码常量写"程序里的门槛"；编的演示数字写"示意"，不要混进真实统计。
   - 不写无法核对的“约 3 万条”却不给出处。
4. **先讲"长什么样/是什么"，再讲"怎么算"。** 观众不知道对象是什么时，讲算法步骤没有落点。
5. **一屏一个结论。** 字幕只补充标题没说清的部分，不重复标题；标题短、动词开头。
6. **结尾停在最后一个事实。** 可列"还没做的事"，不写"为后续奠定基础"这类升华。
7. **讲解对象是观众的疑问，不是我们的讨论记录。** 不回应假想质疑、不写"不是…而是"。

## 二·五 算法类讲解：先拆解机制，再画动画（2026-10-21 定）

算法动画最容易犯的错，是把"结果"演成"过程"：所有线段一起飞、一起变色，观众只看到拼好了，不知道每一步依据什么。开工前先写一张拆解表：

| 输入对象 | 局部操作 | 判定条件 | 成功/失败分支 |
|---|---|---|---|
| 当前对象、相邻对象 | 查找候选邻接 | 距离、方向、类型等条件 | 接受 / 拒绝 / 待定 |

- **从当前处理对象开始**：先选一个对象/节点，按算法真实顺序逐步推进；不要把所有候选对象同时变色。
- **当前对象变色，其他对象保持原色**：未访问候选保持一种颜色，非候选保持另一种；只让当前步可见地改变。
- **把数据结构画出来**：对象集合、相邻关系、状态转移要先画；观众要能看出"当前在哪个节点、有哪些候选边、为什么选这条"。
- **至少演一个失败分支和一个特殊分支**：从真实实现里取两三个最相关的失败/例外，不要只演顺利路径。
- **不把"动画简化"说成算法本身**：如果画面用逐对象生长代替批量合并、用一次演示代替全局优化，要在字幕/卡片注明"动画按逐对象演示，程序实际是批量处理"。
- **先讲数据结构，再讲阈值**：先讲对象之间怎么连、状态怎么变，再讲具体数值；只讲阈值不讲数据结构，观众会把规则误解成另一道工序。
- **实现里没有的机制不要演**：代码里没有搜索/回溯/竞争消解，就不要为了动画效果演成"尝试—失败—退回"；真做了再按真实状态机演。
- **种子的定义要写真实来源**：程序从哪个对象开始（自由端/度≤1、第一个未用、指定起点）必须说清楚；不要用旁边标签给种子命名，演示位置若只是恰好靠近标签，要在字幕注明“示意”，否则观众会以为选择依据是字母。
- **失败原因一次只归因当前规则**：未连接、组件长度不足、无标签、线型组不同是四条不同分支。一个对象同时满足多个条件时，要分别列出或明确“当前演示先触发哪条”，不能压成一句“小于阈值淘汰”。
- **数字要标来源和适用范围**：绝对阈值来自哪几张图、只筛单段还是整条组件、换图族是否要复核，都要在卡片上写清；样本校准值不能讲成普适常数。
- **下游应用和局限说明不属于算法本体**：结果演示、未完成项可以留作收尾，但不要占用机制讲解的时间；标题讲机制时，机制讲完就收。
- **每步有可核对的数字**：阈值写源码常量；示例数字标示意；实测值标来源。
- **抽帧三问**：随机抽一帧，能回答"当前处理哪个对象、依据哪条规则、状态变成了什么"；答不上就是动画没讲清。

## 三、脱敏（2026-10-21 用户定）

教学/讲解类内容默认**不使用真实客户名、零件号、图号、项目代号、真实文件名**。核心是讲清机制，不是交付证据。

- 用通用占位：零件 A / 零件甲、图纸 1 / 图 A、剖切线 A-A；数量级可保留，身份信息去掉。
- 真实截图/图纸：先裁掉标题栏、客户名、图号、签名、人名的区域；非必要不用真实图。
- 需要举例"最短的一条剖切线"时，写"最短的一条"而不是"某某图的某某件"——名字对理解没有帮助。
- 边界：面向工程师/客户的正式技术文档按项目纪律走，不受本条限制；**讲解、教学、对外演示默认脱敏**。拿不准就不写名字。

## 四、文案

初稿写完，独立过一遍 `references/de-ai-rules.md`（与 project-doc 共用）。视频/网页字幕额外注意：

- 字幕是口语的书面化，不是聊天记录：禁"咱们/说白了"，也禁聊天黑话（"踩坑""不吃""重产"）。
- 一句话能删掉而不丢信息，就删。
- 不用四字口号堆节奏；具体名词优先于抽象大词。

## 五、Remotion 工程（可复制骨架）

### 环境与 C 盘红线

- Node ≥ 18；npm 缓存应已指向 `E:\dev-cache`（`npm config get cache` 确认）。
- **依赖装进项目目录**（`node_modules` 在项目内），不装全局。
- Remotion 的 headless Chromium：`npx remotion browser ensure` 下载到 `node_modules/.remotion/`（项目内，不碰 C 盘）。若默认落到 C 盘用户目录，先设 `REMOTION_BROWSER_EXECUTABLE` 或改用系统 Edge/Chrome。
- 渲染临时目录：加 `--bundle-output <项目内目录>`，避免写 C 盘 TEMP。
- 中文直接可用：`font-family: "Microsoft YaHei", "PingFang SC", sans-serif`，不必额外装字体。

### 目录

```
<项目工作目录>/<主题>_remotion/
  package.json
  src/index.ts        registerRoot(Root)
  src/Root.tsx        <Composition id durationInFrames fps width height />
  src/theme.ts        调色板/字体
  src/<Scene>.tsx     SVG 图形组件，按 state 0..1 驱动
  out/                渲染产物（gitignore）
  bundle/             渲染临时打包（gitignore）
  verify/             抽帧验收图（gitignore）
```

`package.json` 依赖：`remotion`、`@remotion/cli`、`react`、`react-dom`（版本对齐，18.x）。

### 命令

```bash
npm install --no-audit --no-fund
npx remotion browser ensure
npx remotion render src/index.ts <CompositionId> out/demo.mp4 --bundle-output bundle --log=error
npx remotion still src/index.ts <CompositionId> verify/f120.png --frame=120 --bundle-output bundle
```

### 时间轴写法

- 1080p / 30fps；帧数 = 秒 × 30；幕边界写成常量（如 `S2=430`），不要在组件里散落魔法数字。
- 用一个 `state` 对象承载每个元素的不透明度/位移，值域 0..1；用 `interpolate(frame, [a,b], [0,1], {extrapolateLeft:"clamp",extrapolateRight:"clamp"})` 生成。
- 幕切换时**显式把上一幕的标注/干扰元素归零**（`dimOut` / `symFade`），否则会串场。
- 转场用淡入淡出，同屏信息不超过 3 组；一幕后停留至少 1 秒再切。

## 六、验收（必须做，不可跳过）

1. **抽关键帧**：每幕 1-2 帧，至少 8 帧，`remotion still` 出 PNG，逐张看：
   - 文字/图元重叠、越界、被遮挡；
   - 上一幕元素残留（红圈、淘汰标记、旧标题）；
   - 标签与对象是否对应（箭头指错、字母挂错线）；
   - 字幕与标题是否重复。
2. 发现问题 → 改源码 → 重渲 → 再抽同一帧复核；不要只看一帧就收工。
3. 检查 mp4：时长、分辨率、体积（1080p 一分钟约 3-5MB 正常）。
4. 交互 HTML 版本：playwright 逐幕截图 + DOM 状态断言（不要只截图不看状态）。

## 七、已知坑（实测）

- **字幕交叠**：两段字幕的 fade 区间重叠，屏幕上两行字叠印。排时间轴时给每段留 200-400ms 空档。
- **状态泄漏**：上一幕的"淘汰标记/红圈"没有随幕退场，串到下一幕的剖视图上。每幕开场先清场。
- **祖先选择器写错**：`.show .badge` 是"父级有 show"，类加在元素自身要用 `.badge.show`；写错不报错、只静默失效。
- **playwright 逐条命令之间页面滚动被重置**：用 `run-code --filename` 把"滚动+等待+截图"写在一个脚本里；截图落盘在 CLI 的工作目录，不在 shell 当前目录。
- **ODAFileConverter 之类的 GUI 工具会弹窗**：命令行批处理也会显示进度窗，改不了；提前告知用户。AutoCAD COM 可隐式但更慢。
- **同名双开**：CAD 里同名图纸打开两次会串；演示/截图前只开一张。

## 八、交付与归档

- 成品：`D:\Desktop\实训文档\个人\<名称>.mp4`（视频）或 `.html`（交互）——讲解类成品统一放这里，不留在工程输出目录。
- 工程：项目工作目录下的 `<主题>_remotion\`；`node_modules/out/bundle/verify` 全部 gitignore。
- 当周日志记一行 ★：做了什么、时长/规格、成品路径、工程路径。
- 讲解内容按第三节脱敏；公开仓库/对外材料里不出现客户名、图号、人名。
